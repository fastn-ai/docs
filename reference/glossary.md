# Glossary

This is the canonical term list for fastn. The dashboard is the authority for names: when a page and the dashboard disagree, the dashboard wins. The **Not** column lists older or informal names that you might still see; don't use them in new writing.

| Term | Definition | Where to find it | Not (also seen as) |
| --- | --- | --- | --- |
| **AI credits** | What the fastn agent and the widget assistant use. Scale includes a monthly allowance and Enterprise has no cap. Launch has no monthly allowance; onboarding adds up to 50 credits. Your AI tool uses no AI credits. | [Billing and limits](../manage/billing.md) | tokens, AI usage |
| **API key** | A credential in `fsk_` format (`fsk_test_` or `fsk_live_`) that authenticates backend API calls, including generating embed tokens. | Embed → API keys (`/api-keys`) | Settings → API keys, Embed → API keys and MCP |
| **App** | Any software a customer uses, such as a CRM, Jira, or Slack. fastn reaches an app through its connector. | [Integrations → Connectors](../build/connectors/the-catalogue.md) | system |
| **Connection** | One signed-in account on a connector, holding its credential. One connector can have many connections (for example, two Slack workspaces). | Operate → Connections | |
| **Connection scope** | One capability of your product's API, such as `billing`. Each customer holds one connection per connection scope. | [Build → Connect your product](../manage/saas-connectors.md) | |
| **Connector** | One app's definition in fastn: its actions, auth methods, and webhooks. fastn maintains a catalog of connectors, and you can create your own (**Create connector** → From scratch, Build with fastn agent, Build in your AI tool, or Import from file). A connector holds no credentials. | Build → Integrations → **Connectors** tab | |
| **Customer** | A company that uses your product. The API names it with `x-org-id` or `orgId`. Each customer's connections and data are isolated. | Operate → Customers | tenant, end customer, client org |
| **Dead Letter Queue (DLQ)** | An option on webhook triggers that captures failed events for later inspection or replay. | Triggers → Webhook → Advanced options | |
| **Embed token** | A short-lived token (8-hour expiry, `emb_` prefix) that your backend generates to scope an embedded widget to one customer. | Generated with the embed token API | |
| **Execution tier** | A workflow's runtime mode: **Instant** (synchronous, up to 25 seconds, or 2 minutes where fastn has turned on the longer Instant timeout), **Standard** (async, up to 15 minutes), or **Long** (async, up to 36 hours). | Workflow editor → Configuration | |
| **fastn agent** | fastn's own builder agent: describe an integration and it picks the connectors, drafts the workflow, and shows the diff. Opened with **Build with fastn agent** (under **Create integration** or **Create connector**) or the prompt on Home. Available on paid plans (Scale or Enterprise) only; it uses AI credits. | [fastn agent](../build/agent/README.md) | Build with AI, AI builder, agent (on its own) |
| **fastn Connect** | fastn's MCP gateway, at `mcp.fastn.dev/<your-org>`. Gives AI agents each customer's connected apps as governed tools, with policies and audit logs. | [fastn MCP server](../build/mcp-gateway/README.md) | fastn MCP gateway |
| **fastn dashboard** | The web app at `app.fastn.dev` that your team uses to set up and run integrations. | `app.fastn.dev` | console, portal, admin panel |
| **fastn MCP server** | `mcp.fastn.dev/fastn-workspace`. Connects your AI tool to your workspace so it can build and manage integrations. Open it with **Connect your AI tool** in the top bar or Embed → MCP server. | Embed → MCP server (`/mcp-server`) | MCP gateway (for this server) |
| **Health** | The first page under Operate. Shows whether your integrations are healthy and the maintainer agent's pending connector updates. | Operate → Health (`/health`) | |
| **Identity hash** | Also written Identity-hmac, or the `x-identity-hmac` header. An HMAC-SHA256 of the org ID and user ID (newline-joined), signed with your identity-verification secret. It proves that your backend authorized that specific org and user pair. | [API keys → Identity hash](../manage/api-keys.md#identity-hash) | |
| **Integration** | Your product working together with an app your customer already uses: a connector, a workflow, a trigger (app event, schedule, or webhook), a connection, and the widget your customers use. | Build → Integrations; [Onboarding → Pick your integrations](../getting-started/onboarding/choose-integrations.md) | automation |
| **Logs** | Everything that ran, in tabs: **Events**, **Executions**, **Sync reports**, and **Monitoring** (Monitoring is for the Owner and Admin roles). Traces is not a tab; it opens at `/activity/traces`. | Operate → Logs (`/activity`) | Activity |
| **Maintainer agent** | The agent that watches connectors for upstream API changes, proposes updates, and diagnoses failures. Its proposals appear as pending updates. | [Operate → Health → Pending updates](../build/connector-updates.md) | update bot |
| **Onboarding** | The guided setup at `/onboarding`. Setup steps: **Check your product**, **Pick your integrations**, **Set up the widget**. Going live: **Add the widget to** your product and **Your first customer connects**, plus the optional **Connect** your product and **Build an integration**. The **Get started** card in the sidebar tracks progress (n of 7). | [Set up fastn](../getting-started/onboarding/README.md) | four steps, Choose integrations, Embed the widget (as a step name) |
| **Operator** | A built-in role in Settings → Roles: configures connections and runs workflows, and deploys to test only. In prose, say **your team** for the people who set up and run integrations. | [Roles](../manage/roles.md) | operator (for the person) |
| **Organization** | In the dashboard, your organization: you, the company that builds the product. Each of your customers is also stored as an organization under yours; you register it in the dashboard or with the [Create a Customer Organization](../embed/embedding/integration-flow.md#create-a-customer-organization) API. API calls identify a customer by fastn's customer id or by your external reference for it (the `orgId` you set, which defaults to the customer's slug if you set none), sent as `x-org-id` or `orgId`. | Operate → Customers | |
| **Organization level / User level** | The two ways an integration's connections can be scoped: shared across a customer's whole organization (**Organization level**) or kept to each user at the customer (**User level**). | Set per integration in the widget (**Scope**) | |
| **Plans** | **Launch** is free. **Scale** and **Enterprise** are the paid plans; building with the fastn agent needs one of them. | Settings → Billing | Growth (retired), Pro |
| **SaaS connector** | Your product's own connector, registered with its connection scopes. The dashboard shows it on Build → Connect your product, under the **API connector** tab. | [Build → Connect your product](../manage/saas-connectors.md) | SaaS connector setup (as a page title) |
| **Trigger** | What starts a workflow. Three types: Webhook, Schedule, App event. | Build → Integrations → **Triggers** tab | |
| **User** | A person at one of your customers who uses the embedded integrations, identified by a user id you choose and send as the `x-user-id` header. Sending a user id is optional. | The `x-user-id` header | end user (except in the "For your customers" introduction) |
| **Widget** | The embedded panel your customers use to connect their apps and manage integrations inside your product. | Embed → Widget (`/widgets`) | |
| **Widget assistant** | The **AI assistant** section of the widget: a prompt box where your customers describe what they want connected, ask questions, and change their configuration in plain words. Turned on in the widget's Layout → Sections. Building new integrations from it needs a paid plan. | [Widget → Layout](../embed/widget-builder/layout.md) | AI Assistant (as a product name) |
| **Workflow** | The code that runs: a JavaScript module that moves and transforms data between apps, step by step. Usually written by the fastn agent or your AI tool from a plain-language description; you can inspect the code. | Build → Integrations → **Workflows** tab | |
| **Your AI tool** | Claude, Cursor, ChatGPT, and similar clients, connected to fastn over MCP through the fastn MCP server. It uses no AI credits. | **Connect your AI tool** in the top bar | external agent, AI tools |
