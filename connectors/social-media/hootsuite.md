# Hootsuite

<img src="../../.gitbook/assets/connectors/lg/hootsuite.png" alt="Hootsuite logo">

This connector covers the Hootsuite Platform REST API 1.0: outbound message scheduling and approval workflows, comment approvals, media uploads, social profiles, the authenticated member, organizations, teams, members and their permissions, and SCIM 2.0 user and group provisioning.

| | |
| --- | --- |
| **Category** | [Social media](README.md) |
| **Website** | [hootsuite.com](https://hootsuite.com) |
| **Authentication** | OAuth 2.0 |
| **Slug** | `hootsuite` |

## Use it

Add Hootsuite from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.hootsuite.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>App Installed Or Uninstalled</td><td><code>com.hootsuite.apps.event.v1</code></td><td>Fires when a member or organization installs or uninstalls the Hootsuite app this connector authenticates as. Delivery requires the callback URL to be set on the app in the Hootsuite dashboard under My Apps &gt; (your app) &gt; Webhooks. This event carries no seq_no.</td></tr><tr><td>Comment State Changed</td><td><code>com.hootsuite.comments.event.v1</code></td><td>Fires whenever a comment moving through the Hootsuite approvals workflow changes state. Hootsuite has no webhook-subscription REST API: the customer must set the callback URL on the app in the Hootsuite dashboard under My Apps &gt; (your app) &gt; Webhooks. Use seq_no to de-duplicate redeliveries.</td></tr><tr><td>Message State Changed</td><td><code>com.hootsuite.messages.event.v1</code></td><td>Fires whenever a scheduled message changes publishing state (for example SCHEDULED to SENT, or to SEND_FAILED_PERMANENTLY). Hootsuite has no webhook-subscription REST API, so delivery must be enabled by the customer in one of two ways: (1) per message, by passing this trigger's URL in the webhookUrls array when calling the Schedule Message action; or (2) for all events of the installed app, by setting the callback URL on the app in the Hootsuite dashboard under My Apps &gt; (your app) &gt; Webhooks. Use seq_no to de-duplicate redeliveries. Endpoints must answer within 10 seconds with a 2xx and a body of 32KB or less.</td></tr><tr><td>Ping</td><td><code>com.hootsuite.ping.event.v1</code></td><td>A connectivity test event Hootsuite sends to confirm a callback URL is reachable and responding. It carries an empty data object and no seq_no. Use it to verify the callback URL configured on the app in the Hootsuite dashboard under My Apps &gt; (your app) &gt; Webhooks before relying on the other events.</td></tr></tbody></table>
