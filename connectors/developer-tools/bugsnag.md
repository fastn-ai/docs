# BugSnag

BugSnag (now SmartBear Insight Hub) is an error monitoring and application stability platform. This connector covers the BugSnag Data Access API: organizations, projects and project settings, errors and error triage, events and event fields, pivots, trends and stability trend, releases and release groups, feature flags and variants, collaborators, teams and project access, saved searches, configured integrations and integration connections, error assignment rules, network endpoint grouping, spans, span groups and traces, SCIM user and group provisioning, and event data export and deletion requests.

## Use it

Add BugSnag from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.bugsnag.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Comment Added | `comment` | Fires when a collaborator adds a comment to an error. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `comment_config` trigger enabled. The payload arrives with `trigger.type` set to `comment`. |
| Error Event Frequency | `errorEventFrequency` | Fires when an error receives the configured number of events or affected users within the configured period. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `error_event_frequency_config` trigger enabled. The payload arrives with `trigger.type` set to `errorEventFrequency`. |
| Error Reopened | `reopened` | Fires when a fixed or snoozed error receives a new event and is automatically reopened. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `reopened_config` trigger enabled. The payload arrives with `trigger.type` set to `reopened`. |
| Error State Manually Changed | `errorStateManualChange` | Fires when a collaborator manually changes an error's workflow state in the BugSnag dashboard. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `error_state_manual_change_config` trigger enabled. The payload arrives with `trigger.type` set to `errorStateManualChange`. |
| Exception | `exception` | Fires on every event received for an error that matches the integration's filters. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `exception_config` trigger enabled. The payload arrives with `trigger.type` set to `exception`. |
| First Exception | `firstException` | Fires the first time an event is received for a new error, once per release stage. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `first_exception_config` trigger enabled. The payload arrives with `trigger.type` set to `firstException`. |
| New Release | `release` | Fires when the project sees a new release, reported automatically or through the BugSnag Build API. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `new_release_config` trigger enabled. The payload arrives with `trigger.type` set to `release`. |
| Power Of Ten Milestone | `powerTen` | Fires when an error reaches an occurrence milestone of 10, 100, 1000 and so on. Registered through the BugSnag Data Access API as a `webhook` data-forwarding configured integration on the project, with the `power_ten_config` trigger enabled.
