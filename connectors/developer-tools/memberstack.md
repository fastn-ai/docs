# Memberstack

<img src="../../.gitbook/assets/connectors/lg/memberstack.png" alt="Memberstack logo">

This connector covers the Memberstack Admin REST API: member listing, retrieval, creation, update and deletion; custom fields, metadata and JSON storage; free-plan assignment and removal; member JWT verification; and the Data Tables API for listing tables and creating, querying, updating and deleting records.

## Use it

Add Memberstack from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.memberstack.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

<table><thead><tr><th width="240">Action</th><th width="260">Slug</th><th>What it does</th></tr></thead><tbody><tr><td>Add Free Plan To Member</td><td><code>addFreePlanToMember</code></td><td>Grants a free plan to an existing member, immediately giving them that plan's permissions and gated content. Only free plans work here; paid plans must go through the Stripe checkout flow in the DOM package or the Stripe Customer Portal. A member can hold several plans at once. A plan ID that does not resolve returns the plan-not-found error.</td></tr><tr><td>Create Data Record</td><td><code>createDataRecord</code></td><td>Creates a record in one of your Memberstack data tables. Data holds the field values keyed by field key, and an optional Member ID assigns a member as the record's owner - the member must belong to the same app and the same live or sandbox environment. A record created without an owner is shown as 'System'.</td></tr><tr><td>Create Member</td><td><code>createMember</code></td><td>Creates a member in your Memberstack app with an email address and, optionally, a password, free plans, custom fields, metadata, JSON storage and a login redirect. Email addresses must be unique within the app. Only free plans (IDs starting with pln_) can be granted here; paid plans require the Stripe checkout flow in the DOM package.</td></tr><tr><td>Delete Data Record</td><td><code>deleteDataRecord</code></td><td>Permanently deletes a record from a Memberstack data table. A table or record that does not exist returns 404 with the message 'Data table not found' or 'Data record not found'.</td></tr><tr><td>Delete Member</td><td><code>deleteMember</code></td><td>Permanently removes a member from your Memberstack app, optionally deleting their Stripe customer and cancelling their Stripe subscriptions at the same time. This cannot be undone. An unknown member ID returns 400 with the message 'There is no member with this identifier.'</td></tr><tr><td>Get Data Table</td><td><code>getDataTable</code></td><td>Retrieves one data table by its key or its ID, including its access rules and the full definition of every field. A table that does not exist returns 404 with the message 'Data table not found'.</td></tr><tr><td>Get Member</td><td><code>getMember</code></td><td>Retrieves a single member by Memberstack ID or by email address. A member that does not exist is not an error: Memberstack answers 200 with data set to null, so assert the data field rather than the status code.</td></tr><tr><td>List Data Tables</td><td><code>listDataTables</code></td><td>Lists every data table in your Memberstack app together with its access rules and field definitions. Tables themselves are created in the Memberstack dashboard; the API manages their records.</td></tr><tr><td>List Members</td><td><code>listMembers</code></td><td>Retrieves a cursor-paginated page of the members in your Memberstack app, each with their authentication email, verification status, custom fields, metadata, permissions and plan connections.</td></tr><tr><td>Query Data Records</td><td><code>queryDataRecords</code></td><td>Queries the records of a Memberstack data table using a Prisma-style query object. Use Find Many with where, orderBy, select or include, take, skip or after and _count to search and page through records, or Find Unique with where.id to fetch exactly one. Find Many and Find Unique are mutually exclusive and one of them is required.</td></tr></tbody></table>
