# Velocify

Velocify LeadManager and Dial-IQ by ICE Mortgage Technology - sales acceleration and lead management for mortgage and high-velocity sales teams. Wraps the live LeadManager ClientService API at service.leads360.com (ASP.NET ASMX, version 1.3.0.0): leads, lead actions and activity logs, agents/users and groups, campaigns, providers, distribution programs, statuses, milestones, custom fields (FormBuilder), Dial-IQ call history and recordings, SMS/email opt-out, direct mail, and custom reports. Credentials are a LeadManager agent email and password sent as request parameters. Responses are XML, not JSON. There is no webhook registration API - poll getLeadsSpan or getLeadIdsSpan for changes.

## Use it

Add Velocify from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.velocify.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Add Agent | `addAgent` | Create a new LeadManager user (agent). SOAP-only on the vendor side because the agent payload is an XML fragment, so this action posts a SOAP 1.1 envelope. Supply agentDataXml as an AddAgent document per AddAgent.Request.xsd, e.g. &lt;AddAgent&gt;&lt;Email&gt;a@b.com&lt;/Email&gt;&lt;FirstName&gt;Jane&lt;/FirstName&gt;&lt;LastName&gt;Doe&lt;/LastName&gt;&lt;Position&gt;Loan Officer&lt;/Position&gt;&lt;WorkPhone&gt;5551234567&lt;/WorkPhone&gt;&lt;ReceivingLeads&gt;true&lt;/ReceivingLeads&gt;&lt;/AddAgent&gt;. Other supported elements: EmailMobile, WorkPhoneExt, MobilePhone, MobilePhoneProvider, Fax, OtherPhone, OtherPhoneExt, Note, Custom1-4, SMSNotificationEnabled, CalendarStartHour, CalendarEndHour, CalendarHighLights, SaveFilterCriteria, Verified, ReceivingCalls. |
| Add Agent Role | `addAgentRole` | Grant a LeadManager security role to a user within a group. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. Supply agentDataXml as an AgentRole document per AddAgentRole.Request.xsd: &lt;AgentRole&gt;&lt;UserEmail&gt;a@b.com&lt;/UserEmail&gt;&lt;Group&gt;Sales&lt;/Group&gt;&lt;Role&gt;Manager&lt;/Role&gt;&lt;/AgentRole&gt;. Group and Role are names, not ids. |
| Add Agent To Group | `addAgentToGroup` | Move a LeadManager user into an agent group. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. Supply groupDataXml as an AddAgentToGroup document per AddAgentToGroup.Request.xsd: &lt;AddAgentToGroup&gt;&lt;UserEmail&gt;a@b.com&lt;/UserEmail&gt;&lt;Group&gt;Sales&lt;/Group&gt;&lt;/AddAgentToGroup&gt;. Group is the group name, not the id. |
| Add Campaign | `addCampaign` | Create a new campaign (lead source) in the LeadManager database. Resolve campaignTypeId with getCampaignTypes and providerId with getProviders. costPerLead feeds the Campaign Cost Assessment report. Returns an XML Response document; HTTP 200 does not imply success, read statusId and message. |
| Add Direct Mail Leads | `addDirectMailLeads` | Load direct mail records into Velocify. These sit in the direct mail pool and only become real leads when a recipient responds and takeDirectMailLeadByDirectMailId or takeDirectMailLeadByRefId converts them. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. Records are keyed by field title rather than field id. |
| Add Email Opt Out | `addOptOut` | Add an email address to the LeadManager opt-out list, suppressing further marketing email to it. Compliance-critical: call this whenever an unsubscribe is recorded upstream. Returns an XML Response document; read statusId and message. |
| Add Field | `addField` | Add a new field to the FormBuilder in the LeadManager database. Resolve fieldTypeId with getFieldTypes, visibilityTypeId with getVisibilityTypes and groupId with getFieldGroups. The new FieldId is returned and can then be used in lead reads and writes. Returns an XML Response document; read statusId and message. |
| Add Field Group | `addFieldGroup` | Add a new field group (lead form section) to the FormBuilder in the LeadManager database. The new FieldGroupId is returned and can then be passed as groupId to addField. Returns an XML Response document; read statusId and message. |
| Add Lead Action | `addLeadAction` | Log an activity (action) against an existing lead - a call attempt, email, note or any tenant-defined action type. ActionTypeIds are per-tenant; resolve them with getActionTypes, which also reports whether a note is mandatory for that action type. Logging an action is what fires any Manage Posts outbound post configured against that action. Returns an XML Response document; HTTP 200 does not imply success. |
| Add Leads | `addLeads` | Create one or more leads. This is the only way to create a lead through the API. Velocify exposes it over SOAP only, because the lead payload is an arbitrary XML fragment, so this action posts a SOAP 1.1 envelope. Supply leadsXml as a Leads document, e.g. &lt;Leads&gt;&lt;Lead&gt;&lt;Status StatusId="2"/&gt;&lt;Campaign CampaignId="3"/&gt;&lt;Agent AgentId="1"/&gt;&lt;Fields&gt;&lt;Field FieldId="2" Value="John"/&gt;&lt;Field FieldId="4" Value="a@b.com"/&gt;&lt;/Fields&gt;&lt;/Lead&gt;&lt;/Leads&gt;. No child node is required; omitted Status and Campaign fall back to the tenant defaults and an omitted Agent leaves the lead unassigned. FieldIds are per-tenant - resolve them with getFields. Each lead is reported individually in the response, so a 200 can still contain per-lead failures. |
| Add Leads With Form Type | `addLeadsEx` | Create one or more leads, with the ability to set the LeadFormType on each. Identical to addLeads apart from that. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. Resolve available form types with getLeadFormTypes and FieldIds with getFields. Each lead is reported individually, so a 200 can still contain per-lead failures. |
| Assign Lead Via Distribution | `assignViaDistribution` | Assign a lead to an agent through a Velocify distribution program, so the assignment respects the program's routing rules, shark-tank and notification behaviour rather than bypassing them. Resolve programId with getPrograms and pick an eligible agentId with getAgentsQualified or getQualifiedAgents for that program and lead. Returns an XML Response document. |
| Copy Lead | `copyLead` | Duplicate an existing lead, creating a new lead record from it. Note the parameter is capitalised LeadId on this operation, unlike the rest of the API. Returns an XML Response document carrying the new lead's result. |
| Deactivate Agent | `deactivateAgent` | Deactivate a LeadManager user by email address, revoking their access. Use disableReceiveLeads instead if you only want to stop routing new leads to them while keeping them active. Returns an XML Response document. |
| Delete Call Recordings | `deleteCallRecordings` | Delete Dial-IQ call recordings within an inclusive date/time range. Destructive and typically used for retention or right-to-erasure compliance. The response reports how many recordings were deleted, how many deletions failed, and whether more remain in the window - re-run until PossibleRecordingsRemaining reports none. |
| Delete SMS Opt Out | `deleteSmsOptOut` | Opt phone numbers back in to SMS messaging, clearing their SMS opt-outs. The WSDL declares phoneNumbers (ArrayOfString) alongside the credentials, and the vendor operation page documents it as "The Phone Numbers to Opt In to SMS Messaging". ASP.NET binds a repeated phoneNumbers query parameter to that array, so pass one phone number per repetition. Returns an XML Response document. |
| Disable Receive Leads For Agent | `disableReceiveLeads` | Stop routing new leads to an agent without deactivating their account, identified by email address. Typically used to take a loan officer out of distribution while they are out of office. Returns an XML Response document. |
| Get Action Types | `getActionTypes` | Return the action types available in the LeadManager database, each reporting whether a note is mandatory, whether it counts as a contact attempt, and which milestone and distribution program it belongs to. Resolve actionTypeId here before calling addLeadAction. Returns an XML ActionTypes document. |
| Get Agent | `getAgent` | Return a single user (agent) by AgentId, with contact details, position, group membership and the four custom agent fields. Returns an XML Agents document. |
| Get Agent Groups | `getGroups` | Return the agent groups (teams) in the LeadManager database, with their active flag. Use this to resolve groupId for getAgentsInGroup and addAgentToGroup. Returns an XML Groups document. |
| Get Agents | `getAgents` | Return every user (agent) in the LeadManager database, with contact details, position, group membership and the four custom agent fields. Use this to resolve AgentIds for modifyLeadAgent, assignViaDistribution and lead creation. Returns an XML Agents document. |
| Get Agents In Group | `getAgentsInGroup` | Return the users (agents) belonging to a specific agent group. Resolve groupId with getGroups. Returns an XML Agents document. |
| Get Agents Qualified For Lead | `getAgentsQualified` | Return the users available to receive a specific lead under a given distribution program. Call this before assignViaDistribution to pick a valid agent. Returns an XML Agents document. |
| Get Call History Report | `getCallHistoryReport` | Return every Dial-IQ call in the call history report for a date/time range, with duration, origin, segment, wait time, result, the lead and agent involved, and the recording URL. The API has no pagination, so keep the window narrow. Returns an XML Calls document. |
| Get Campaign Groups | `getCampaignGroups` | Return the campaign groups in the LeadManager database. Campaign groups bundle campaigns for reporting. Returns an XML CampaignsGroups document. |
| Get Campaign Types | `getCampaignTypes` | Return every campaign type available in LeadManager. Use this to resolve campaignTypeId before calling addCampaign. Returns an XML CampaignTypes document. |
| Get Campaigns | `getCampaigns` | Return the campaigns in the LeadManager database, with type, cost per lead, active flag, response code, provider and campaign group. Use this to resolve CampaignIds for lead creation and modifyLeadCampaign. Returns an XML Campaigns document. |
| Get Direct Mail Leads | `getDirectMailLeads` | Search the direct mail pool. Hard-capped at 50 results by the vendor, and there is no pagination, so narrow the search rather than expecting to page through. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. The search is expressed as SearchItem elements keyed by field title. |
| Get Distribution Audit Log | `getDistributionAuditLog` | Return the distribution audit trail for a lead or a call - every routing attempt, which program ran, which step fired, which agents were notified and how. Use this to diagnose why a lead went to a particular loan officer, or did not. Returns an XML DistributionAuditLog document. |
| Get Distribution Programs | `getPrograms` | Return the lead distribution programs in the LeadManager database, with their type and enabled flag. Distribution programs are Velocify's routing rules. Use this to resolve programId for assignViaDistribution and the qualified-agent lookups. Returns an XML Programs document. |
| Get Field Groups | `getFieldGroups` | Return the FormBuilder field groups in the LeadManager database. Field groups are the sections a lead form is divided into. Resolve groupId here before calling addField. Returns an XML FieldGroups document. |
| Get Field Types | `getFieldTypes` | Return every FormBuilder field type available in LeadManager (text, number, date, picklist and so on). Resolve fieldTypeId here before calling addField. Returns an XML FieldTypes document. |
| Get Fields | `getFields` | Return every FormBuilder field in the LeadManager database, with its type, group, required and visibility settings, plus the picklist items for choice fields. This is the schema-discovery call for the whole connector - FieldIds are per-tenant and every lead read and write is keyed on them. Returns an XML Fields document. |
| Get Last Created Lead | `getLastCreatedLead` | Return the most recently created lead in the LeadManager database. Takes no arguments beyond credentials, so it is the cheapest call for verifying that a connection works. Returns an XML Leads document. |
| Get Last Modified Lead | `getLastModifiedLead` | Return the most recently modified lead in the LeadManager database. Takes no arguments beyond credentials. Returns an XML Leads document. |
| Get Lead | `getLead` | Return a single lead by its LeadManager LeadId, with its campaign, status, owning agent, all custom field values, export markers and full activity logs (action, assignment, creation, distribution, email and status logs). Responds with an XML Leads document, not JSON. Dates are MM/DD/YYYY HH:MM:SS in server time. |
| Get Lead And Qualified Agents By Phone | `getLeadAndQualifiedAgentsByPhone` | Inbound-call routing primitive. Finds the most recently created lead matching a phone number, optionally stamps up to two fields on it, and returns the agents qualified to take that lead under a distribution program. Typically driven by a dialer or IVR at call pickup. Resolve programId with getPrograms, campaignId with getCampaigns and the field ids with getFields. |
| Get Lead And Qualified Agents By Phone With Lead | `getLeadAndQualifiedAgentsByPhoneWithLead` | Variant of getLeadAndQualifiedAgentsByPhone that returns the full lead record alongside the qualified agents. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. The WSDL types the fields argument as ArrayOfFieldValue, so FieldId and Value are wrapped in fields/FieldValue; the vendor contract is unbounded but this action stamps exactly one field per call. |
| Get Lead Form Types | `getLeadFormTypes` | Return the lead form types configured in the LeadManager database. Lead form types are the per-tenant lead layouts; addLeadsEx can set one at creation time. Returns an XML document. |
| Get Lead IDs By Create Date | `getLeadIds` | Return only the IDs of leads created within a date/time range, based on CreateDate. Much cheaper than getLeads for wide windows - fetch the IDs first, then call getLead per ID. Returns an XML Leads document of bare Lead elements carrying only Id. |
| Get Lead IDs By Create Date With Scope | `getLeadIdsEx` | Return the IDs of leads created within a date/time range, restricted by a visibility scope. Same as getLeadIds plus a scope selector, which controls whether the calling agent sees only their own leads or the wider database. Returns an XML Leads document of bare Lead elements carrying only Id. |
| Get Lead IDs Modified In Last N Minutes | `getLeadIdsSpan` | Return only the IDs of leads modified in the past X minutes, based on ModifyDate. The cheapest change-detection call in the API - pair it with a fastn scheduler and fan out to getLead for the records you care about. Returns an XML Leads document of bare Lead elements carrying only Id. |
| Get Leads By Create Date | `getLeads` | Return full lead records created within a date/time range, based on CreateDate. The API has no pagination - the time window is the only way to bound the result set, so keep windows narrow because each lead carries its fields and full logs. Dates are interpreted in Velocify server time (PST); call getServerTime to align. Responds with an XML Leads document. |
| Get Leads By Email | `getLeadsByEmail` | Search for leads by email address. Use this for de-duplication before creating a lead. Returns the same XML Leads document as getLead. |
| Get Leads By Phone | `getLeadsByPhone` | Search for leads by phone number. Typically used for inbound-call screen pops and for de-duplication. Returns the same XML Leads document as getLead. |
| Get Leads Modified In Last N Minutes | `getLeadsSpan` | Return full lead records modified in the past X minutes, based on ModifyDate. This is the change-detection primitive for Velocify - the product has no webhook registration API, so pair this action with a fastn scheduler whose interval matches fromNowMinutes to poll for lead changes. Responds with an XML Leads document. |
| Get Milestones | `getMilestones` | Return the lead milestones configured in the LeadManager database. Milestones group action types into funnel stages and are referenced by MilestoneId on action types. Returns an XML Milestones document. |
| Get Providers | `getProviders` | Return the lead provider integrations configured in the LeadManager database. Providers are the upstream lead vendors that campaigns map to. Use this to resolve providerId for addCampaign. Returns an XML Providers document. |
| Get Qualified Agents With Lead | `getQualifiedAgents` | Return the users qualified to receive a specific lead under a distribution program, together with the lead's own information. Differs from getAgentsQualified in that the lead record comes back alongside the agent list. |
| Get Report Results | `getReportResults` | Execute a custom report by id, supplying values for its template filter items, and return the rows. SOAP-only on the vendor side because the template values are an XML fragment, so this action posts a SOAP 1.1 envelope. Call getReports first to find the FilterItemIds whose IsTemplate is true. Note the vendor strips spaces from field titles in the result element names. |
| Get Report Results Without Filters | `getReportResultsWithoutFilters` | Execute a custom report by id and return its rows, ignoring the report's filter items. Use this for reports with no template filters; use getReportResults when the report has template values to supply. Note the vendor strips spaces from field titles in the result element names. Resolve reportId with getReports. |
| Get Reports | `getReports` | Return the custom reports defined in the LeadManager database, each with its filter items and select items. A filter item marked IsTemplate is one you must supply a value for when calling getReportResults. Use this to resolve reportId and discover which template values a report needs. Returns an XML Reports document. |
| Get Server Time | `getServerTime` | Return the current date and time from the Velocify data server, in PST. Takes no credentials. Use it to align the from/to windows of getLeads and getLeadIds, which are interpreted in server time, not UTC. Responds with XML. |
| Get Statuses | `getStatuses` | Return the lead statuses configured in the LeadManager database. Statuses are per-tenant; use this to resolve StatusIds before calling modifyLeadStatus or setting a status on lead creation. Returns an XML Statuses document. |
| Get Version | `getVersion` | Return the current version of the Velocify LeadManager web service, format x.x.x.x. Takes no credentials - useful as a reachability check for the configured base URL. Responds with an XML document, not JSON. |
| Get Visibility Types | `getVisibilityTypes` | Return every field visibility type available in LeadManager, which controls whether a field is shown to users. Resolve visibilityTypeId here before calling addField. Returns an XML VisibilityTypes document. |
| Modify Agent | `modifyAgent` | Update an existing LeadManager user (agent). SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. Supply agentDataXml as an EditAgent document per EditAgent.Request.xsd: &lt;EditAgent&gt;&lt;Email&gt;current@b.com&lt;/Email&gt;&lt;NewEmail&gt;new@b.com&lt;/NewEmail&gt;&lt;FirstName&gt;Jane&lt;/FirstName&gt;...&lt;/EditAgent&gt;. | Modify Agent Password | `modifyAgentPassword` | Set a new LeadManager password for an agent, identified by email address. Note the new password is sent as agentPassword; the password parameter remains the calling agent's own credential. Returns an XML Response document. |
| Modify Lead Agent | `modifyLeadAgent` | Reassign an existing lead to a different agent (owner). AgentIds are per-tenant - resolve them with getAgents. | Modify Lead Campaign | `modifyLeadCampaign` | Move an existing lead to a different campaign. CampaignIds are per-tenant - resolve them with getCampaigns. Returns an XML Response document; HTTP 200 does not imply success, read statusId and message. |
| Modify Lead Field | `modifyLeadField` | Set a single custom field value on an existing lead. FieldIds are per-tenant - resolve them with getFields first, and make sure the value matches the field's data type. For multi-field updates in one call use modifyLeads instead. Returns an XML Response document; HTTP 200 does not imply success, read statusId and message. |
| Modify Lead Status | `modifyLeadStatus` | Change the status of an existing lead. StatusIds are per-tenant - resolve them with getStatuses. A status change is what fires any Manage Posts outbound post configured against that status in the LeadManager admin UI. Returns an XML Response document; HTTP 200 does not imply success. |
| Modify Leads | `modifyLeads` | Update one or more existing leads in a single call - status, campaign, owning agent, flag and any set of custom fields together. Prefer this over repeated modifyLeadField calls. SOAP-only on the vendor side, so this action posts a SOAP 1.1 envelope. The Id attribute on each Lead element is required for modification, unlike addLeads. Only the nodes you include are touched; omitted nodes are left alone. |
| Post SMS Opt Out | `postSmsOptOut` | Opt a phone number out of SMS messaging. Compliance-critical for TCPA. The contact id is optional on the vendor side but this action sends both; pass the lead id the number belongs to. Use deleteSmsOptOut to opt numbers back in. Returns an XML Response document. |
| Remove Campaign | `removeCampaign` | Delete a campaign from the LeadManager database. Destructive. Prefer setting a campaign inactive over removing it if leads still reference it. Returns an XML Response document with a Removals element; read statusId and message. |
| Remove Lead | `removeLead` | Delete a lead from the LeadManager database. Destructive and not reversible through the API. Returns an XML Response document with a Removals element; HTTP 200 does not imply success, read statusId and message before treating the lead as gone. |
| Take Direct Mail Lead By Direct Mail ID | `takeDirectMailLeadByDirectMailId` | Convert a direct mail record into a real lead using its direct mail id, assigning it to an agent. | Take Direct Mail Lead By Ref ID | `takeDirectMailLeadByRefId` | Convert a direct mail record into a real lead using the unique reference id printed on the mail piece, assigning it to an agent.
