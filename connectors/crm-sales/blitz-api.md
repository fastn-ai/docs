# Blitz API

Blitz API is B2B go-to-market data infrastructure for growth and revenue teams. It provides verified contact data on 380M+ professionals: person and company enrichment (work email, mobile phone, reverse email/phone lookup, full company firmographics), ICP company and people search, waterfall decision-maker search, live job-posting search, and TAM-by-hiring-signal account lists. This connector uses the vendor's hosted Model Context Protocol server, so the tool surface is discovered live from Blitz and always matches the current API.

## Use it

Add Blitz API from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.blitzApi.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| account_key_info | `account_key_info` | Get your API key's account details: plan, remaining records, and rate limits. Input: none. Returns: account and key info (`records_remaining` is a number, or the string "unlimited" on unmetered plans). Cost: 0 records. |
| company_employees_by_country | `company_employees_by_country` | Get a company's employee headcount distribution bucketed by ISO 3166-1 alpha-2 country code. Input: `company_linkedin_url`, optional `is_recent_hire`. Returns: `found`, `company_linkedin_url`, `total_employees` and a `distribution` list of `country` (ISO code, or `unknown`), `count` and `percentage_ratio` (0-100). Cost: 1 record on success. |
| company_employees_by_department | `company_employees_by_department` | Get a company's employee headcount distribution bucketed by department (unclassified employees counted under `Other`). Input: `company_linkedin_url`, optional `is_recent_hire`. Returns: `found`, `company_linkedin_url`, `total_employees` and a `distribution` list of `department`, `count` and `percentage_ratio` (0-100). Cost: 1 record on success. |
| company_enrich | `company_enrich` | Get one company's full firmographic record from its LinkedIn URL. Use for a single known company; use company_search to discover companies by filters. Input: `company_linkedin_url`. Returns: `found` and `company` (LinkedIn URL and id, name, about, specialties, industry, type, size, employee count on LinkedIn, followers, founded year, headquarters, domain, website, and `mx` mail records of the domain), or `company: null` when the company has no data. Cost: 1 record. |
| company_find_by_domain | `company_find_by_domain` | Find a company's LinkedIn URL from its web domain (inverse of company_get_domain). Input: `domain`. Returns: a company LinkedIn URL. Cost: 1 record. |
| company_get_domain | `company_get_domain` | Get a company's web domain from its LinkedIn URL (inverse of company_find_by_domain). Input: `company_linkedin_url`. Returns: the web domain under the `email_domain` field. Cost: 1 record on success. |
| company_search | `company_search` | Find companies by firmographic filters (name keywords, industry, type, size, geo). Use to build an account list from company attributes; use company_tam_by_jobs to build it from hiring demand instead. Input: a `company` filter block (nest all firmographic filters under `company`), `max_results`, `cursor`. Returns: `results` (companies, each with LinkedIn URL and id, name, about, specialties, industry, type, size, employee count on LinkedIn, followers, founded year, headquarters, domain and website; no employees, email or phone number), `total_results` (all matching companies), `results_length`, `max_results` and a `cursor` for the next page (null at the end). Cost: 1 record per result. |
| company_tam_by_jobs | `company_tam_by_jobs` | Turn hiring demand into a target-account list: the distinct companies posting jobs that match your filters, deduped, each with a matched-jobs count. Input: `job` and `company` filters (optionally `job.min_per_company`), `max_results`, `cursor`. Returns: companies each with a `matched_jobs` count. Cost: 1 record per result. |
| company_tam_by_people | `company_tam_by_people` | Turn a person-level ICP into a target-account list: the distinct companies whose current employees match your filters, deduped, each with a matched-employees count. Use when the account signal is workforce makeup (who works there); use company_tam_by_jobs when it's hiring demand. Input: `people` and `company` filters (optionally `people.min_per_company`), `max_results`, `cursor`. Returns: companies each with a `matched_people` count. Cost: 1 record per result. |
| docs_read | `docs_read` | Read or browse specific Blitz documentation pages via a read-only, filesystem-style query rooted at '/'. Use after docs_search to open a page in full. |
| docs_search | `docs_search` | Search the Blitz documentation (guides, concepts, API reference, and examples) and get matching snippets with titles and links. Use this to learn how a Blitz endpoint works before calling it. Returns a text list of matching snippets, each with the page title and a link to the page, cut to about 4,000 characters; open a page in full with docs_read. |
| job_search | `job_search` | Search job postings across all companies by job filters (title, location, and more). Use for jobs across the market; use job_search_by_company to scope to one company. Input: a `job` filter block plus an optional `company` firmographic block, `max_results`, `cursor`. Returns: job postings. Cost: 1 record per result. |
| job_search_by_company | `job_search_by_company` | Search the job postings of ONE company by job filters. Use to scope a job search to a single company; use job_search for the whole market. Input: `company_linkedin_url` plus `job` filters, `max_results`, `cursor`. Returns: job postings. Cost: 1 record per result. |
| people_employee_finder | `people_employee_finder` | List the current employees of ONE company by seniority/function/geo — no free-text title, paged. Use for a company roster; use people_search for a title/ICP query across companies. Input: `company_linkedin_url` plus flat enum filters (`country_code`, `job_level`, `job_function`; `country_code` defaults to `WORLD` = no geo filter), `max_results`, `page`. Returns: `results` (people, each with name, headline, about, location, LinkedIn URL, connections count, `experiences`, education, skills and certifications; `experiences` holds the job at that company), `results_length`, `page`, `total_pages` and `company_linkedin_url`. No email or phone number is returned; use people_find_work_email or people_find_phone. Cost: 1 record per result. |
| people_enrich | `people_enrich` | Get one person's profile and whole career history from their LinkedIn URL. Use for a single known person; use people_search to discover people by filters, or people_lookup_by_email / people_lookup_by_phone to start from a contact detail. Input: `person_linkedin_url`. Returns: a person. Cost: 1 record on success. |
| people_find_phone | `people_find_phone` | Find a person's mobile and direct phone numbers from their LinkedIn URL. US numbers only — skip non-US people. Inverse of people_lookup_by_phone. Input: `person_linkedin_url`. Returns: phone number(s). Cost: 1 record on success. |
| people_find_work_email | `people_find_work_email` | Find a person's work email(s) from their LinkedIn URL. Inverse of people_lookup_by_email. Input: `person_linkedin_url`. Returns: email(s). Cost: 1 record on success. |
| people_lookup_by_email | `people_lookup_by_email` | Reverse lookup: find the person behind an email address (inverse of people_find_work_email). Input: `email`. Returns: `found` and `person` (name, headline, about, location, LinkedIn URL, connections count, `experiences`, education, skills and certifications; `experiences` holds the full career), or `person: null` when no one matches. Cost: 1 record on success. |
| people_lookup_by_phone | `people_lookup_by_phone` | Reverse lookup: find the person behind a phone number (inverse of people_find_phone). Input: `phone`. Returns: `found` and `person` (name, headline, about, location, LinkedIn URL, connections count, `experiences`, education, skills and certifications; `experiences` holds the full career), or `person: null` when no one matches. Cost: 1 record on success. |
| people_search | `people_search` | Find people across many companies by ICP filters (firmographic company filters plus person title/level/function/geo; free-text or `[exact]` titles). Use for a title/ICP query spanning companies; for one company's roster use people_employee_finder. Input: `company` and `people` filter blocks, `max_results`, `cursor`. Returns: `results` (people, each with name, headline, about, location, LinkedIn URL, connections count, `experiences`, education, skills and certifications; `experiences` holds the job that matched, not the whole career), `total_results`, `results_length`, `max_results` and a `cursor` for the next page (null at the end). No email or phone number is returned; use people_find_work_email or people_find_phone. Cost: 1 record per result. |
| people_waterfall_icp | `people_waterfall_icp` | Find the best-fit people at ONE company by priority title tiers (cascade: try tier-1 titles, fall back to tier-2, and so on, stopping at `max_results`). Use when you have ranked title preferences for a single company; use people_employee_finder for a flat roster. Input: `company_linkedin_url` plus an ordered `cascade` of tiers (each with `include_title`/`exclude_title` and a `location`). Returns: `company_linkedin_url`, `results_length` and `max_results` (both the number of people found) and `results`, each with `person` (name, headline, about, location, LinkedIn URL, connections count, `experiences`, education, skills and certifications; `experiences` holds the job that matched), `icp` (the number of the tier that found the person, from 1) and `ranking` (position in the list, from 1). No email or phone number is returned; use people_find_work_email or people_find_phone. Cost: 1 record per result. |
| send_feedback | `send_feedback` | Send feedback, a bug report, a feature request, or praise directly to the Blitz team — about the Blitz API, data quality, the docs, or this MCP server. Use whenever the user wants to reach the Blitz team. Returns a short text confirmation that the feedback was recorded; it returns no ticket id and no reply. |
| util_changelog | `util_changelog` | Get Blitz API changelog entries, newest first. Input: optional `days` and `limit`. Returns: a list of entries, each with `date` (UTC, YYYY-MM-DD), `type` (breaking, feature, improvement, fix, deprecation or announcement), `title`, and optional `body` (markdown), `affected_endpoints` and `links`. Cost: 0 records. No API key required. |
| util_current_date | `util_current_date` | Get the current date and time in a given timezone. Input: `region` (IANA timezone). Returns: `datetime` (YYYY-MM-DD HH:mm:ss in that zone), `timestamp` (Unix seconds), `timezone` and `timezone_name`. Cost: 0 records. |
