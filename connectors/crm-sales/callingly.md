# Callingly

<img src="../../.gitbook/assets/connectors/lg/callingly.png" alt="Callingly logo">

This connector covers the full Callingly REST API (v1): calls, leads, SMS, teams, team agent routing and caps, agents (users) and their availability schedules, agency client accounts, and outbound webhook subscriptions for call completed, lead created and lead updated events. Authenticates with a Callingly API key sent as a Bearer token.

## Use it

Add Callingly from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.callingly.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Call Completed</td><td><code>call_completed</code></td><td>Fires when a Callingly call finishes (inbound or outbound). Registered through POST /v1/webhooks with event call_completed; each registration targets one event, so routing is per subscription. Callingly does not document the delivered payload or sign deliveries. The schema below is modelled on the documented Get Call response and has not been reconciled against a live delivery, because triggering one requires placing a real phone call.</td></tr><tr><td>Lead Created</td><td><code>lead_created</code></td><td>Fires when a new lead is created in Callingly. Registered with event lead_created; routing is per subscription. The schema below is modelled on the documented Get Lead response and has not been reconciled against a live delivery, because Callingly only creates leads through a real call or inbound lead source.</td></tr><tr><td>Lead Updated</td><td><code>lead_updated</code></td><td>Fires when a Callingly lead changes. Registered with event lead_updated, optionally narrowed with Create Webhook's field (lead_owner, result, stage, status, tags) and filter. Routing is per subscription. The schema below is modelled on the documented Get Lead response and has not been reconciled against a live delivery.</td></tr><tr><td>SMS Sent or Received</td><td><code>sms</code></td><td>Fires for Callingly SMS messages. This event value is accepted by the live Callingly webhooks API (verified by validation) but is not described in the public documentation. Routing is per subscription. The schema below is modelled on the documented Send SMS response and has not been reconciled against a live delivery, because triggering one requires sending a real SMS.</td></tr></tbody></table>
