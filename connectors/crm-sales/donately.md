# Donately

Donately is an online fundraising and donation platform for nonprofits, churches and businesses, offering embeddable donation forms, campaign and peer-to-peer fundraising pages, recurring giving, text-to-give and donor management. This connector wraps the Donately REST API v2 at https://api.donately.com/v2: accounts and their payment sources, processors and referrals, donations with refunds, receipts and e-cards, campaigns, people (donors), peer-to-peer fundraisers, recurring subscriptions, donation forms, email notifications and notification templates, text-to-give codes, charges, account statistics, webhooks with their retry history, and the PayPal, Stripe and Tray.io partner connection status endpoints.

## Use it

Add Donately from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.donately.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Add Account Payment Source | `createAccountPaymentSource` | Stores a billing card on the Donately account itself, used for Donately's own subscription fees. Takes a single-use tokenised card from Stripe.js or the Donately checkout - raw card numbers are never accepted. ATTACHES A REAL CARD: only call it with a token for a card the organisation owns. |
| Create Account | `createAccount` | Creates a brand-new Donately account (organisation) with its own public donation pages. terms must be accepted or Donately rejects the request. IRREVERSIBLE: Donately exposes no endpoint for deleting an account, so every account created this way is permanent and may be billable. |
| Create Campaign | `createCampaign` | Creates a fundraising campaign on the connected Donately account. Two Donately behaviours to know: every new campaign is published immediately, so its public page at pages.donately.com is live as soon as this call returns and there is no draft state; and the campaign type is always 'general' - Donately's real type values are general, p2p_fundraisers, p2p_teams and earmark, but it accepts any of them on the wire and stores 'general' regardless, so peer-to-peer must be turned on in the Donately dashboard. start_date and end_date are likewise accepted and never stored. Only title and goal_in_cents are required; a goal below $1.00 is rejected. |
| Create Donation | `createDonation` | Records a donation on the connected Donately account. donation_type 'cash' or 'ach' records an offline gift with no money movement (processor is reported as N/A); 'cc' and 'paypal' charge the donor and need a payment token from the Donately or processor checkout. IMPORTANT: always supply the donor email - with no email Donately silently creates a brand-new placeholder Person (dntlymail+...@donate.ly), and it does so even when the request is then rejected for validation, and Donately has no endpoint for deleting a person, so those placeholder donors are permanent. meta_data is stored on create but is discarded by Update Donation. |
| Create Form | `createForm` | Creates a new embeddable donation form on the connected Donately account. form_config is required - Donately rejects the request with 'Form config can't be blank' without it - and carries the widget settings as a JSON string, for example {"amount":"100","payment_options":"cc"}. |
| Create Fundraiser | `createFundraiser` | Creates a peer-to-peer fundraiser page under a campaign. email and campaign_id are both required (Donately answers 'Request missing required fields: ...'). The campaign must be a peer-to-peer campaign: a general campaign is refused with a 405 'Fundraisers not allowed for that campaign.' Donately's campaign type cannot be changed through the API - it is accepted on the wire and always stored as 'general' - so the campaign has to be switched to Peer to Peer in the Donately dashboard first. The public page goes live as soon as the call returns, and a new email creates a permanent Person record. |
| Create HTML Content | `createHtmlContent` | Creates a custom HTML block attached to a donation form - the tribute e-card text Donately renders for in-honour and in-memory gifts, and the e-card footer. template is required and validated: it must be ecard_honor, ecard_memory or ecard_footer, and Donately answers 'You must include a template type' when it is missing and 'Template is not included in the list' when it is unrecognised. form_id names the form the block belongs to. Donately exposes no retrieve-one or delete route for these blocks: read them back with List HTML Contents (filter by form_id) and change one with Update HTML Content. |
| Create Notification | `createNotification` | Creates a notification rule that emails an account administrator when a Donately event occurs. All four fields are required and each is validated against a fixed Donately list - a missing or unrecognised value is rejected with 'Notification type is not included in the list, Event is not included in the list, and Frequency is not included in the list'. Only notification_type 'email' and frequency 'daily_digest' are accepted, and the recipient is named by person_id (an administrator of the account), not by a raw email address. Once created the rule sends REAL EMAIL to that administrator. |
| Create Person | `createPerson` | Creates a person (donor) record on the connected Donately account. Donately validates the email for deliverability and rejects undeliverable domains with 'Email address did not pass validation'; an address already on the account is rejected with 'A person with that email address already exists, try update instead.' IRREVERSIBLE: Donately exposes no endpoint for deleting a person, so every record created here is permanent. |
| Create Text-to-Give Keyword | `createTextToGive` | Creates a text-to-give keyword, so donors can text a code to give. code and message are both required and each must be at least three characters - Donately rejects the request with 'Code can't be blank, and Code must be at least 3 characters' otherwise. The keyword becomes live on the account's SMS number as soon as the call returns. The created id uses the t2g_ prefix. amount_in_cents is echoed back as accepted and never stored, so it is not offered here. |
| Create Webhook | `createWebhook` | Subscribes a URL to one Donately event. One webhook carries exactly one hook, so subscribe several times for several events. hook must be one of the seven Donately accepts (listed on the field) - anything else is rejected with 'Hook is not included in the list'. post_url must be an absolute http:// or https:// URL. The created webhook's id uses the hok_ prefix. Donately records every delivery attempt: read them with List Webhook Retries and re-send one with Rerun Webhook Retry. Delete Webhook is the unsubscribe. |
| Delete Campaign | `deleteCampaign` | Permanently deletes a fundraising campaign from the connected Donately account and takes its public page offline. This is the only way to unpublish a campaign through the API. Donations already attributed to the campaign are not deleted. |
| Delete Donation | `deleteDonation` | Permanently deletes a donation record from the connected Donately account. This removes the record only; it does not refund money. Deleting a donation does not delete the donor Person that Donately created alongside it, and Donately exposes no way to delete a person. |
| Delete Form | `deleteForm` | Permanently deletes an embeddable donation form. Any page still embedding the form stops accepting gifts. Donations already taken through the form are not deleted. The account default form cannot be removed this way - make another form default first. |
| Delete Fundraiser | `deleteFundraiser` | Permanently deletes a peer-to-peer fundraiser and takes its public page offline. Donations already raised through the fundraiser are not deleted, they simply lose the fundraiser attribution. |
| Delete Notification | `deleteNotification` | Permanently deletes a notification rule, so the account stops emailing that recipient on that event. |
| Delete Text-to-Give Keyword | `deleteTextToGive` | Permanently deletes a text-to-give keyword, so texting that code no longer starts a gift. Donations already made through the keyword are not deleted. |
| Delete Webhook | `deleteWebhook` | Deletes a webhook subscription, so Donately stops posting that event to the URL. This is the unsubscribe call for a Donately event subscription. |
| List Account Referrals | `listAccountReferrals` | Lists the organisations this Donately account has referred through the Donately referral programme. Requires the Donately-Version 2021-11-15 API version, which this connector pins; on the older default version the route does not exist. |
| List Accounts | `listAccounts` | Lists the Donately accounts (organisations) visible to the connected API key, with each account's title, subdomain, public donation page URL, currency and status. |
| List Available Tray.io Solutions | `listTrayAvailableSolutions` | Lists the third-party integrations Donately offers through Tray.io, with each solution's id, title and description. Requires the Donately-Version 2021-11-15 API version, which this connector pins; the route does not exist on the older default version. |
| List Campaigns | `listCampaigns` | Lists the fundraising campaigns on the connected Donately account, with a summary of the total count and the amount raised. Campaign type is the only filter Donately actually applies on this endpoint: it echoes title, status, form_id, donation_type, email, unique_identifier, start_date and end_date back as accepted and then returns the unfiltered list, so those are deliberately not offered here. The four real type values were recovered from Donately's own dashboard - 'peer_to_peer' is not one of them and matches nothing. |
| List Charges | `listCharges` | Lists the individual processor charges taken on the connected Donately account. A charge is the payment-processor transaction behind a donation; the donation record itself is returned by List Donations. Donately exposes no single-charge retrieve route. |
| List Donations | `listDonations` | Lists the donations recorded on the connected Donately account, newest first by donation date, with a summary of the total count, total amount and donor count. Filters proven to work: campaign, fundraiser, payment type, currency, status and live mode. Donately echoes email, form_id, state and unique_identifier back as accepted on this endpoint and then returns the unfiltered list, so they are deliberately not offered. |
| List Forms | `listForms` | Lists the embeddable donation forms on the connected Donately account, including which one is the account default and each form's version and configuration. |
| List Fundraisers | `listFundraisers` | Lists the peer-to-peer fundraisers on the connected Donately account, with a summary of the total count and the amount raised across them. |
| List HTML Contents | `listHtmlContents` | Lists the custom HTML blocks stored on the connected Donately account - the tribute e-card in-honour, in-memory and footer text attached to donation forms. Pass form_id to list only one form's blocks. Requires the Donately-Version 2021-11-15 API version, which this connector pins; the route does not exist on the older default version. |
| List My Accounts | `listMyAccounts` | Lists the Donately accounts the person who owns the connected API key is an administrator of. Use List Accounts for every account the key can read. |
| List My Donations | `listMyDonations` | Lists the donations made by the person the connected API key belongs to, across every Donately account they have given to. Use List Donations instead to list an organisation's incoming donations. Donately echoes email, form_id, state and unique_identifier back as accepted on this endpoint and then returns the unfiltered list, so they are deliberately not offered. |
| List My Fundraisers | `listMyFundraisers` | Lists the peer-to-peer fundraisers owned by the person the connected API key belongs to, across every Donately account. Use List Fundraisers for an organisation's own fundraisers. |
| List My Subscriptions | `listMySubscriptions` | Lists the recurring giving subscriptions of the person the connected API key belongs to, across every Donately account they give to. Use List Subscriptions for an organisation's incoming recurring gifts. |
| List Notifications | `listNotifications` | Lists the notification rules on the connected Donately account - which staff addresses are emailed on which event, and how often. |
| List People | `listPeople` | Lists the people (donors and administrators) known to the connected Donately account, with each person's email, name and giving totals. |
| List Subscriptions | `listSubscriptions` | Lists the recurring giving subscriptions on the connected Donately account, with their amount, interval, status and donor. Donately has no create or delete route for subscriptions - they are started by a donor at checkout and ended by updating the status. |
| List Tax Receipts | `listTaxReceipts` | Lists the tax-receipt summary for the person the connected API key belongs to: their deductible giving grouped by organisation, with totals for the period. Use Send Tax Statement to email a donor their statement. |
| List Text-to-Give Keywords | `listTextToGives` | Lists the text-to-give keywords on the connected Donately account - the SMS codes donors text to give, with the reply message and campaign each is wired to. |
| List Tray.io Solution Instances | `listTraySolutionInstances` | Lists the Tray.io integration instances the connected Donately account has configured. Returns a 400 with 'Error finding 3rd party integration user' when the account has never opened the integrations area, so no Tray.io user exists for it yet. |
| List Webhook Retries | `listWebhookRetries` | Lists the delivery attempts Donately has made for one webhook subscription, each with the exact JSON payload it posted, the event it came from and the HTTP status the endpoint returned. webhook_id is required - Donately returns a 400 with 'Request missing required fields: webhook_id' without it. Attempt ids use the wha_ prefix. |
| List Webhooks | `listWebhooks` | Lists the webhook subscriptions on the connected Donately account, each with the event it listens for (its hook) and the URL Donately posts to. |
| Make Form Default | `makeFormDefault` | Makes a donation form the account default, so it is the form served wherever no specific form is named. Exactly one form is default at a time; the form that was default loses the flag. |
| Recalculate Account Statistics | `recalculateStatistics` | Recalculates the cached giving statistics of one Donately account. The path segment is an ACCOUNT id, not a statistics id - Donately answers an unknown value with 'No Account was found with that ID.' Use Retrieve Statistics to read the figures back. |
| Refund Donation | `refundDonation` | Refunds a processed donation through the payment processor that took it. MOVES REAL MONEY - a full refund is issued when no amount is given, and the refund cannot be undone. Offline cash and cheque donations have no processor and cannot be refunded. |
| Rerun Webhook Retry | `rerunWebhookRetry` | Re-sends a failed webhook delivery to its subscription URL. The receiving endpoint gets the original event payload again, so it must tolerate a duplicate delivery. |
| Retrieve Account | `getAccount` | Retrieves a single Donately account (organisation) by its account id, including its title, subdomain, public page URL, currency, status and totals raised. |
| Retrieve Account Payment Source | `getAccountPaymentSource` | Retrieves the card Donately has on file for billing the organisation itself (not a donor card): brand, last four digits and expiry. Every field is null when no billing card is stored. |
| Retrieve Campaign | `getCampaign` | Retrieves a single fundraising campaign on the connected Donately account by its campaign id, including its goal, amount raised, status and public page URL. |
| Retrieve Donation | `getDonation` | Retrieves a single donation on the connected Donately account by its donation id, including the amount, payment method, status, donor and the campaign or fundraiser it was attributed to. |
| Retrieve Form | `getForm` | Retrieves a single embeddable donation form by its form id, including its version, configuration and whether it is the account default. |
| Retrieve Form Config | `getFormConfig` | Retrieves just the rendering configuration of a donation form - suggested amount, accepted payment options and account currency - as the embedded widget loads it. This is the only form route that answers for a form id the account does not own, returning the account default configuration instead of a 404. |
| Retrieve Fundraiser | `getFundraiser` | Retrieves a single peer-to-peer fundraiser by its fundraiser id, including its goal, amount raised, owner and public page URL. |
| Retrieve My Person | `getMyPerson` | Retrieves the Donately person record behind the connected API key - the identity the key acts as. Useful as a cheap credential check: it needs no inputs and returns the owning email. |
| Retrieve Notification | `getNotification` | Retrieves a single notification rule by its notification id, including its type, the event it fires on, its frequency and the recipient. |
| Retrieve Payment Processors | `getUpdatedProcessors` | Retrieves the payment processor configuration of the connected Donately account: the default processor and currency, live mode, and the Stripe and PayPal connection state. Use it to check whether the account can actually take card or PayPal gifts before creating a donation. |
| Retrieve PayPal Merchant ID | `getPaypalMerchantId` | Retrieves the PayPal merchant id linked to the connected Donately account. Returns a 404 with the message RESOURCE_NOT_FOUND_ERROR, passed straight through from PayPal, when the account has never completed PayPal onboarding. |
| Retrieve PayPal Merchant Status | `getPaypalMerchantStatus` | Retrieves the PayPal onboarding status of the connected Donately account - whether payments and receiving are enabled. Returns a 400 with 'This Donately account is not connected to Paypal.' when no PayPal account is linked. |
| Retrieve PayPal Onboarding URL | `getPaypalReferralsUrl` | Creates a PayPal partner-referral link the organisation follows to connect its PayPal account to Donately. Returns PayPal's own action_url in the links array; the link is single-use and short-lived. |
| Retrieve Person | `getPerson` | Retrieves a single person by their person id, including their contact details and giving history with this organisation. |
| Retrieve Statistics | `getStatistics` | Retrieves the giving statistics of the connected Donately account - totals raised, donation and donor counts, and averages - as the dashboard reports them. |
| Retrieve Stripe Account | `getStripeAccount` | Retrieves the Stripe Connect account behind the connected Donately account, including its charges and payouts state. Returns a 400 with 'Error Getting Stripe Account' when the account has no Stripe connection. |
| Retrieve Stripe Account Link | `getStripeAccountLink` | Creates a Stripe Connect onboarding link the organisation follows to connect or finish setting up its Stripe account. Returns a 400 with 'This Donately account is not linked to a Stripe account.' when no Stripe account exists yet. |
| Retrieve Subscription | `getSubscription` | Retrieves a single recurring giving subscription by its subscription id, including the amount, interval, next charge date, status and donor. |
| Retrieve Tax Statement Status | `getTaxStatementStatus` | Reports whether the account's batch tax statement has already been emailed this year, which tax year it covers and how many donors it would reach. Read it before calling Send Tax Statements - this is the status mode of the same Donately route, selected by the check_tax_statement_status flag, and it sends nothing. |
| Retrieve Text-to-Give Keyword | `getTextToGive` | Retrieves a single text-to-give keyword by its id, including the SMS code, the automatic reply and the campaign the gift is attributed to. |
| Retrieve Tray.io Config Wizard URL | `getTrayConfigWizardUrl` | Creates a Tray.io configuration wizard link for one of Donately's third-party integration solutions, which the organisation follows to finish setting the integration up. solution_id is required - Donately returns a 400 with 'Missing 3rd party integration solution Id' without it. Get the id from List Available Tray.io Solutions. |
| Retrieve Webhook | `getWebhook` | Retrieves a single webhook subscription by its webhook id, including the event it listens for, the URL Donately posts to and its delivery counters (success_count, fail_count, last_attempt_status). |
| Retrieve Webhook Retry | `getWebhookRetry` | Retrieves a single webhook delivery attempt by its id, including the payload Donately sent and the response the endpoint returned. |
| Run Subscription Now | `runSubscriptionNow` | Charges a recurring giving subscription immediately instead of waiting for its next scheduled date. MOVES REAL MONEY: it bills the donor's stored card straight away and the charge cannot be undone except by refunding the resulting donation. |
| Send Admin Password Reset | `sendAdminPasswordReset` | Emails a Donately password-reset link to an administrator of the account. SENDS A REAL EMAIL to the administrator address - only call it when that person has asked to reset their password. |
| Send Donation E-Card | `sendDonationEcard` | Sends the tribute e-card attached to a donation to its recipient. SENDS A REAL EMAIL to the e-card recipient - use only for a gift that genuinely carries a tribute or memorial e-card. |
| Send Donation Receipt | `sendDonationReceipt` | Re-sends the donation receipt email for a donation to the donor. SENDS A REAL EMAIL to the donor address on the donation - only call it for a gift whose donor genuinely needs another copy of their receipt. |
| Send Donor Report | `sendDonorReport` | Queues the account's annual donor report and emails a download link. The period is fixed to the last complete calendar year and is chosen by Donately - start_date and end_date are accepted on the wire and silently ignored (proven: a request naming 2026-01-01..2026-06-30 came back with report_start_date 2025-01-01, report_end_date 2025-12-31), so they are not offered here. SENDS A REAL EMAIL - only call it for an address that has asked for the report. |
| Send Tax Statements | `sendTaxStatement` | Queues the annual tax statement email to EVERY donor on the account - this is Donately's batch send, and batch_all true is the only parameter combination it accepts ('Missing parameters' otherwise). SENDS REAL EMAIL TO EVERY DONOR, once per year per account: check first with Retrieve Tax Statement Status, which reports the tax year, the donor count and whether the batch has already gone out. |
| Send Test Email Receipt | `sendTestEmailReceipt` | Sends a sample donation receipt to the connected account's own email address so the receipt template can be checked. SENDS A REAL EMAIL, to the account's own address only. Use Send Donation Receipt to re-send a real donor's receipt. |
| Send Test Notification | `sendTestNotification` | Sends a sample tribute e-card to the connected account's own address so the e-card template can be checked, using the subject, body and footer supplied rather than the stored ones. type is required and Donately accepts only 'ecard' - anything else is rejected with 'notification of type: &lt;value&gt; is incorrect'. SENDS A REAL EMAIL, to the connected account's own address. Use Send Test Email Receipt for the receipt template. |
| Update Account | `updateAccount` | Updates a Donately account (organisation). Donately uses POST for updates and merges only the fields supplied, so omitted fields keep their current values. Changing the subdomain changes the public donation page URL immediately. |
| Update Campaign | `updateCampaign` | Updates a fundraising campaign on the connected Donately account. Donately uses POST for updates and merges only the fields supplied, so omitted fields keep their current values. Changing the title also regenerates the public page slug and URL. Two fields are accepted and then ignored, so they are not offered here: status (a campaign cannot be unpublished through the API - delete it instead) and type (re-verified with Donately's real value p2p_fundraisers, which is still stored as 'general'). |
| Update Donation | `updateDonation` | Updates an existing donation on the connected Donately account. Donately uses POST, not PATCH or PUT, and merges only the fields supplied, leaving everything else untouched. Use it to re-attribute a gift to a campaign or fundraiser, change the donor comment, or flag it anonymous. Donately accepts note and meta_data on this endpoint and then discards them, so they are deliberately not offered here. |
| Update Form | `updateForm` | Updates an embeddable donation form. Donately uses POST for updates and merges only the fields supplied. Changing form_config changes the live embedded widget immediately on every page it is embedded on. |
| Update Fundraiser | `updateFundraiser` | Updates a peer-to-peer fundraiser. Donately uses POST for updates and merges only the fields supplied, so omitted fields keep their current values. |
| Update HTML Content | `updateHtmlContent` | Updates a custom HTML block on the connected Donately account. WARNING - unlike every other Donately update this one REPLACES rather than merges: any of title or content you leave out is set to null on the stored record (proven by write-then-read-back), so always send both. The new body is used the next time the e-card is rendered, so changing it changes what real tribute-gift recipients see. |
| Update Last Login | `updateLastLogin` | Stamps the current time as the last-login time of the person the connected API key belongs to. Donately's own dashboard calls this on sign-in; it returns data true and changes nothing else. |
| Update Notification | `updateNotification` | Updates a notification rule. Donately uses POST for updates and merges only the fields supplied. Changing the recipient redirects every future notification email for that rule. |
| Update Person | `updatePerson` | Updates a person (donor) record. Donately uses POST for updates and merges only the fields supplied, so omitted fields keep their current values. Changing the email changes where that donor's receipts are sent. Note the phone field is called phone_number here - Donately accepts a plain 'phone' silently and never stores it. |
| Update Subscription | `updateSubscription` | Updates a recurring giving subscription. Donately uses POST for updates and merges only the fields supplied. This is also how a subscription is cancelled - Donately has no delete route for subscriptions, so set the status instead. CHANGES WHAT A REAL DONOR IS CHARGED: altering amount_in_cents or the interval changes their next and every later payment. |
| Update Text-to-Give Keyword | `updateTextToGive` | Updates a text-to-give keyword. Donately uses POST for updates and merges only the fields supplied. Changing the reply message changes what real donors receive by SMS from the next gift onwards. |
| Update Webhook | `updateWebhook` | Updates a webhook subscription - its delivery URL, event or title. Donately uses POST for updates and merges only the fields supplied. hook is validated against the same seven-event list as Create Webhook. |

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Campaign created | `account.campaign.create.success` | A fundraising campaign was created on the account. Payload schema captured from a real Donately delivery on 2026-09-21. Note the delivered payload's type_string drops the 'account.' prefix: it reads 'campaign.create.success'. |
| Donation created | `account.donation.create.success` | A donation was recorded on the account. Envelope shape captured live from a campaign.create delivery; object is 'donation' and object_data is the donation record as Retrieve Donation returns it (modelled from that action's response, not from a captured donation delivery). |
| Donation updated | `account.donation.update.success` | A donation record was changed. Not listed in Donately's own support article; proven to be an accepted hook against the live API. Envelope captured live; object_data modelled from the donation record. |
| Donor details updated | `account.person.pii.update.success` | A person's personal details changed. Recovered from the integration metadata Donately's own Tray.io solutions subscribe to (HubSpot, Salesforce, Mailchimp, Constant Contact) and proven to be an accepted hook against the live API; it is in neither Donately's support article nor any third-party spec. Envelope captured live; object_data modelled from the person record. |
| Fundraiser created | `account.fundraiser.create.success` | A peer-to-peer fundraiser page was created. Envelope captured live; object_data modelled from the fundraiser record. Only fires on accounts with peer-to-peer campaigns enabled in the Donately dashboard. |
| Recurring gift failed | `account.subscription.recur.failure` | A recurring giving subscription failed to charge. Envelope captured live; object_data modelled from the subscription record. |
| Recurring gift updated | `account.subscription.update.success` | A recurring giving subscription was changed, including cancellation. Not listed in Donately's own support article; proven to be an accepted hook against the live API. Envelope captured live; object_data modelled from the subscription record. |
