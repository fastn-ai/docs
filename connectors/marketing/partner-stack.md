# PartnerStack

<img src="../../.gitbook/assets/connectors/lg/partner-stack.png" alt="PartnerStack logo">

PartnerStack is a partner relationship management (PRM) platform for affiliate, referral, reseller and ambassador programs. This connector covers the full PartnerStack REST API v2 at https://api.partnerstack.com/api — primarily the Vendor API: partnerships (partners) and partner teams, partner applications, groups, tiers and tier collections, referral links, customers, transactions, rewards, actions, leads and deals (including convert, files and form templates), product books and products, sales-cycle stages, custom reports and record exports, and webhook management. It also covers the three Partner API endpoints that have no vendor equivalent: payouts and the partner marketplace of programs. Two auth methods: Vendor API keys over HTTP Basic (public key as username, secret key as password) and a Partner API key sent as a Bearer token; each action's description states which one it needs. Events are delivered through PartnerStack's webhook registration API.

## Use it

Add PartnerStack from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.partnerStack.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Add Partner Team Member | `addPartnerTeamMember` | Vendor API (Basic auth). Invites or adds a person to the partner team behind a partnership, so several people at the partner company can work the same program. Set create_user true to provision a user account if the email is not already a PartnerStack user. from_email controls who the invite appears to come from and defaults to the vendor owner. |
| Archive Action | `archiveAction` | Vendor API (Basic auth). Archives a recorded action. Destructive by cascade: any rewards or drip rewards generated from the action are archived with it, so a partner's earned commission disappears. Use it only to correct an action recorded in error. |
| Archive Deal | `archiveDeal` | Vendor API (Basic auth). Archives a registered deal, removing it from the active pipeline. There is no unarchive endpoint. To record a lost deal while keeping it visible, set stage and lost_reason with updateDeal instead. |
| Archive Lead | `archiveLead` | Vendor API (Basic auth). Archives a lead, removing it from the active pipeline. Accepts either the PartnerStack lead key (lead_...) or the external_key you assigned. There is no unarchive endpoint. |
| Archive Partnership | `archivePartnership` | Vendor API (Basic auth). Archives a partnership, removing the partner from your program. Archived partnerships are excluded from listPartnerships unless include_archived is true. Set delete_links true to also delete their referral links, which permanently breaks any link already in circulation. |
| Assign Partnership To Deal | `assignPartnershipToDeal` | Vendor API (Basic auth). Assigns a partnership, and a specific person on that partner team, to an existing deal. Use it to route a vendor-sourced deal to a channel partner, or to re-attribute one. All three identifiers travel in the path. Note this endpoint sits on the legacy non-versioned path /api/deals/... rather than /api/v2/.... |
| Bulk Decision Applications | `bulkDecisionApplications` | Vendor API (Basic auth). Approves or declines many partner applications in one call. The same decision, group override, manager and tags are applied to every key in application_keys. Note this variant takes group_id_override (numeric) only; use decisionApplication one at a time when you need the group_key_override form. |
| Bulk Move Partnerships To Group | `bulkUpdatePartnerships` | Vendor API (Basic auth). Moves a set of partners to a different group in one call. Pass the partner_keys to move and the destination group_key. Use updatePartnership instead when changing a single partner or when you also need to set a tier, manager or custom fields. |
| Convert Deal | `convertDeal` | Vendor API (Basic auth). Converts a won deal into a tracked customer, carrying the attribution to the registering partner across so later transactions generate their rewards. email is required; customer_key defaults to the email of the deal being converted. |
| Convert Lead | `convertLead` | Vendor API (Basic auth). Converts a lead into a tracked customer, preserving the attribution to the partner who submitted it, so subsequent transactions on that customer generate their rewards. If customer_key or email are omitted, the lead's external_key is used for both. |
| Create Application | `createApplication` | Vendor API (Basic auth). Submits a partner-program application on behalf of an applicant - the API equivalent of your public application form, for when applications are captured on your own site. group_slug names the group applied to (the slug, not the key; see listGroups). The application lands as pending and is decided with decisionApplication. |
| Create Customer | `createCustomer` | Vendor API (Basic auth). Creates a customer and attributes it to a partner via partner_key. Important limitation stated by PartnerStack: this endpoint cannot associate the signup with a referral link or click, so landing-page and partner attribution for signups, paid customers and revenue will be incomplete. For attributed signups use Server-to-Server tracking instead; use this endpoint for backfills, imports and customers whose attribution you already know. Creating with Test API keys marks the customer as a test customer. |
| Create Deal | `createDeal` | Vendor API (Basic auth). Registers a deal. account_name, amount (in CENTS), close_date, contact_first_name, contact_last_name and stage are all required. stage must be a value from the Deal Stage list in the relevant group's settings - list the valid ones with listSalesCycleStages using object_type deal. Name the submitting partner team member with either personal_stack_key or team_member_email, not both. |
| Create Lead | `createLead` | Vendor API (Basic auth). Creates a lead on behalf of a partner - the API path for pushing your own inbound leads down to channel partners. external_key must be unique across all leads in your program and is how you address the lead later. partner_key names the partner credited with it; company, first_name and last_name go in the meta object. |
| Create Partnership | `createPartnership` | Vendor API (Basic auth). Creates a new partnership, i.e. adds a partner to your program. The partnership starts with claimed = false until the partner claims it; set notify_by_email true to send them a verification email. If you supply partner_key it must be unique across your program, otherwise PartnerStack generates one. group_key places the partner in a specific group (use listGroups to find it); omit it for the default group. |
| Create Product | `createProduct` | Vendor API (Basic auth). Creates a product instance for a customer from a product book - the record that a specific customer holds a specific product. product_book_key, customer_key and status are required. Set external_subscription_key to your billing-system subscription id so churn and upgrades reconcile. |
| Create Product Book | `createProductBook` | Vendor API (Basic auth). Creates a product book - a product definition in your catalogue. Set external_key to your billing-system product id (Stripe, Chargebee) so products and transactions reconcile against it, and so getProductBook can be called with that id. |
| Create Reward | `createReward` | Vendor API (Basic auth). Creates a reward (a commission or bonus) for a target. target.type chooses what the reward hangs off: customer or transaction attributes it to that record's partner, and manual pays a partnership directly - for manual, target.key is the partnership key. amount is in integer CENTS. There is no update or delete endpoint for rewards, so get the amount and target right first time. |
| Create Tier | `createTier` | Vendor API (Basic auth). Creates a tier inside an existing tier collection. criteria holds the rules a partner must meet to reach the tier; benefits is the list shown to partners, each with a name, description and display order. Create the collection first with createTierCollection. |
| Create Tier Collection | `createTierCollection` | Vendor API (Basic auth). Creates a tier collection - the container for a ladder of tiers plus the cycle on which partners are re-evaluated. Only a name is needed at creation; add tiers with createTier and configure the cycle with updateTierCollection. |
| Create Transaction | `createTransaction` | Vendor API (Basic auth). Records a transaction against a tracked customer, which is what drives revenue-share rewards. The customer must be referenced by exactly one of customer_key, customer_external_key or customer_email - supplying more than one is an error. amount is in integer CENTS of the given currency. Test API keys may only record transactions against test customers. |
| Create Webhook | `createWebhook` | Vendor API (Basic auth). Registers a webhook: PartnerStack POSTs a {event, data} body to target_url whenever any of the subscribed events fires. events must contain at least one value from the supported enum; the docs page lists a few extra names the API will reject. PartnerStack signs nothing and offers no shared secret, so the target URL must be unguessable. This action backs the fastn connector event subscription. |
| Decision Application | `decisionApplication` | Vendor API (Basic auth). Approves or declines one partner application. Set approved true to admit the partner, false to decline (pair it with decline_reason). You can also land the approved partner in a different group than the one applied to with group_key_override, assign a partner manager, and apply tags in the same call. |
| Delete Customer | `deleteCustomer` | Vendor API (Basic auth). Deletes a customer by key. Destructive: the customer's attribution to their partner goes with them, which affects reporting on transactions and rewards already tracked against that customer. |
| Delete Product | `deleteProduct` | Vendor API (Basic auth). Deletes a product instance by internal key (prod_...) or external subscription key. For a subscription that simply ended, prefer updateProduct with status churned - that preserves the history a report would need. |
| Delete Product Book | `deleteProductBook` | Vendor API (Basic auth). Deletes a product book by internal key (pbook_...) or external product key. Product instances created from this book reference it, so remove or re-point those first. |
| Delete Transaction | `deleteTransaction` | Vendor API (Basic auth). Deletes a transaction by key. Destructive: rewards already calculated from this transaction are affected, so prefer this only for correcting mistakes, e.g. a double-recorded payment. |
| Delete Webhook | `deleteWebhook` | Vendor API (Basic auth). Archives a webhook. Events stop being delivered to its endpoint immediately. This action backs the fastn connector event unsubscription. |
| Export Base Records | `exportBaseRecords` | Vendor API (Basic auth). Queues a bulk export of raw base records - the way to pull a full history of partners, customers, transactions or rewards rather than a saved report. The export runs on behalf of member_email and is filtered to the record types that member can access; if none of the requested types are accessible the call returns 403. Poll the returned key with getVendorReportExport. |
| Export Custom Report | `exportCustomReport` | Vendor API (Basic auth). Requests an export of a saved custom report. The export is asynchronous and can take up to 30 minutes; it is emailed to the member and, if you supply webhook_target_url, POSTed there on completion. You can also poll getVendorReportExport with the returned key. Rate limited: one export per report per 2 hours and 20 exports per teammate per 2 hours, over which it returns 429. |
| Get Custom Report | `getCustomReport` | Vendor API (Basic auth). Retrieves one saved custom report definition by key - its name, type, creator and whether it has a scheduled export. This returns the definition only, not the report data; use exportCustomReport for rows. |
| Get Customer | `getCustomer` | Vendor API (Basic auth). Retrieves one customer by key. The key is the same external customer_key you assign through PartnerStackJS or createCustomer. Returns the customer profile plus the partner and partner team they are attributed to. |
| Get Deal | `getDeal` | Vendor API (Basic auth). Retrieves one registered deal by its PartnerStack key (deal_...) or by the external_key configured for it. Returns the account and contact, amount in cents, close date, stage, and the partner team and team member who registered it. |
| Get Deal File URL | `getDealFile` | Vendor API (Basic auth). Returns a download URL for one file attached to a deal. The response is JSON containing data.url, not the file bytes, so fetch the URL separately to retrieve the content. Note this endpoint sits on the legacy non-versioned path /api/deals/... rather than /api/v2/.... |
| Get Deal Form Templates | `getDealFormTemplates` | Vendor API (Basic auth). Returns the deal-registration form templates (molds) configured for your program - the custom fields partners fill in when registering a deal. Call this to discover each field's api_name before setting values through the fields array on createDeal or updateDeal. Narrow by group, mold or partner. |
| Get Lead | `getLead` | Vendor API (Basic auth). Retrieves one lead by its PartnerStack key (lead_...) or by the external_key you assigned. Returns the prospect details in meta, the submitting partner and team member, the sales-cycle stage and any custom field values. |
| Get Lead Form Templates | `getLeadFormTemplates` | Vendor API (Basic auth). Returns the lead form templates (molds) configured for your program, i.e. the custom fields partners fill in when submitting a lead. Call this to discover the api_name of every custom field before setting values through the fields array on createLead or updateLead. Narrow by group, mold or partner. |
| Get Marketplace Program | `getMarketplaceProgram` | PARTNER API ONLY - requires a connection made with the Partner API Key (Bearer) auth method. Retrieves one marketplace-listed program by its company key, returning the vendor's name, description, logo, website, country, categories and whether the program supports sub IDs. |
| Get Partner Team | `getPartnerTeam` | Vendor API (Basic auth). Retrieves a partner team by its stack key (stck_...), returning the team name, the partner_key and partnership_key it maps to, and its network approval status. The team stack key appears on partnership, deal and message payloads. |
| Get Partnership | `getPartnership` | Vendor API (Basic auth). Retrieves one partnership. The identifier is flexible: pass the partner-facing partner_key, the internal partnership key (part_...), or the partner's email address. Returns the partner's profile, group, tier, tags, manager, team and address. |
| Get Product | `getProduct` | Vendor API (Basic auth). Retrieves one product instance. The identifier accepts either the internal PartnerStack key (prod_...) or the external subscription key from your billing system, so a Stripe or Chargebee subscription id works directly. |
| Get Product Book | `getProductBook` | Vendor API (Basic auth). Retrieves one product book. The identifier accepts either the internal PartnerStack key (pbook_...) or the external billing key you set at creation, so you can look it up by your Stripe or Chargebee product id directly. |
| Get Report Export | `getVendorReportExport` | Vendor API (Basic auth). Retrieves an export by key - the polling half of exportCustomReport and exportBaseRecords. file_url and file_name are populated only once the export has finished and has not expired; until then read status, and error if it failed. Archived exports can still be retrieved. |
| Get Tier | `getTier` | Vendor API (Basic auth). Retrieves one tier by key, including its threshold, criteria and its position in the collection via next_tier_key and prev_tier_key. Note the response nests the object one level deeper than most endpoints, at data.tier. |
| Get Tier Collection | `getTierCollection` | Vendor API (Basic auth). Retrieves one tier collection by key, including every tier in it. Note the response nests the object one level deeper than most endpoints, at data.tier_collection. |
| Get Webhook | `getWebhook` | Vendor API (Basic auth). Retrieves one registered webhook by key, returning its target URL and subscribed event types. |
| List Actions | `listActions` | Vendor API (Basic auth). Returns a cursor-paginated list of PartnerStack actions - recorded events performed by a partner or a customer (a trial start, a certification, a demo booked) that reward rules can trigger on. Not to be confused with reward records. Filter by partnership, customer, action type or a specific action key. Also works with a Partner API key. |
| List Applications | `listApplications` | Vendor API (Basic auth). Returns a cursor-paginated list of applications submitted to your partner program, newest first. Filter by status (pending, approved, declined, or flagged for fraud), by applicant email, or by the group applied to. Poll for status=pending to drive an approval workflow. |
| List Custom Reports | `listCustomReports` | Vendor API (Basic auth). Lists the custom reports saved by your team in the PartnerStack Performance tab. This returns the report definitions only, never their data - to get rows, call exportCustomReport with a report key and then poll getVendorReportExport for the file URL. |
| List Customers | `listCustomers` | Vendor API (Basic auth). Returns a cursor-paginated list of the customers tracked in PartnerStack, newest first by default. A customer is an end user attributed to a partner. Filter by the referring partner (partner_key or partnership_key), by group, by specific customer keys, or by created/updated time. Also works with a Partner API key, where it returns only that partner's referred customers. |
| List Deal Files | `listDealFiles` | Vendor API (Basic auth). Lists the files a partner attached to a deal, e.g. quotes, scoping documents or signed paperwork. Returns file metadata and keys; use getDealFile with a file key to obtain a downloadable URL. |
| List Deals | `listDeals` | Vendor API (Basic auth). Returns a cursor-paginated list of registered deals, newest first. A deal is a qualified opportunity registered by a partner, with an account, an amount in cents and an expected close date. Filter by partner, group, customer keys, a specific deal key, or created/updated time. Poll with min_updated to sync deals into a CRM as opportunities. |
| List Disti Listing Categories | `listDistiListingCategories` | Vendor API (Basic auth). Returns the AppDirect-aligned category taxonomy used by the distribution-listing create flow. Each entry carries the stable AppDirect id, PartnerStack's slug, the display name and the product line. Reference data - call it to populate a category picker. |
| List Form Templates | `listFormTemplates` | Vendor API (Basic auth). Returns every form template (mold) in your program across all object types - the custom-field definitions behind applications, partner profiles, leads, deals, customers, links, announcements and MDF requests. Use target_type to narrow to one object. This is the general discovery call for custom-field api_names; getLeadFormTemplates and getDealFormTemplates are the lead and deal shortcuts. |
| List Groups | `listGroups` | Vendor API (Basic auth). Returns the groups in your program. A group is a partner segment (Affiliates, Resellers, Ambassadors) carrying its own reward rules, deal and lead settings, and application form. Read-only over the API - groups are created in the PartnerStack dashboard. Call this to resolve the group_key needed by createPartnership, updatePartnership and bulkUpdatePartnerships, and the slug needed by createApplication. |
| List Leads | `listLeads` | Vendor API (Basic auth). Returns a cursor-paginated list of leads submitted by partners, newest first. A lead is a prospect a partner has handed you, before it is qualified into a deal. Filter by submitting partner, group, a specific lead key, or created/updated time. Poll this with min_updated to sync leads into a CRM. |
| List Marketplace Programs | `listMarketplacePrograms` | PARTNER API ONLY - requires a connection made with the Partner API Key (Bearer) auth method. Returns the active programs listed on the PartnerStack marketplace: the partner programs a partner can discover and apply to. Filter by marketplace category. There is no vendor-side equivalent of this endpoint. |
| List Partnership Links | `listPartnershipLinks` | Vendor API (Basic auth). Lists the referral links belonging to one partnership - the tracked URLs a partner shares to earn attribution. The identifier is flexible: partner email, partnership_key or partner_key. Read-only over the API; links are created by the partner or in the dashboard. Each item carries the shareable url, its destination, and whether it is the partner's default link. |
| List Partnerships | `listPartnerships` | Vendor API (Basic auth). Returns a cursor-paginated list of the partnerships in your PartnerStack program, newest first by default. A partnership is the relationship between your company and one partner (affiliate, referral partner or reseller). Also works with a Partner API key, where it instead returns the programs that partner belongs to. With a Vendor API key, filter by group name, partner email, approved status, or created/updated time. With a Partner API key, only order_by, has_sub_id, include_offers and include_archived apply; other filters are ignored. Page with limit (max 250, default 10) plus starting_after or ending_before, using an item key as the cursor. |
| List Payouts | `listPayouts` | PARTNER API ONLY - requires a connection made with the Partner API Key (Bearer) auth method, not the vendor Basic keys. Returns a cursor-paginated list of the authenticated partner's payouts: money actually withdrawn from PartnerStack, as opposed to rewards earned. There is no vendor-side equivalent of this endpoint. |
| List Product Books | `listProductBooks` | Vendor API (Basic auth). Returns a cursor-paginated list of product books - the catalogue of products a customer can hold, used to attach product-level context to commissions. Search by keyword across name and description. Use the returned key as product_book_key on createProduct. |
| List Products | `listProducts` | Vendor API (Basic auth). Returns a cursor-paginated list of product instances - the actual subscriptions or purchases a customer holds, each created from a product book. Filter by customer, by the partner member stack key, or by the click that drove it. status tracks trial, active and churned. |
| List Rewards | `listRewards` | Vendor API (Basic auth). Returns a cursor-paginated list of rewards - the commissions and bonuses owed to partners. Amounts are integer cents. This endpoint carries the richest filter set in the API: by partnership, group, customer, invoice, drip schedule, status, currency, how the reward was created, or free-text keywords across reward key, customer name and partner name/email. Also works with a Partner API key, which additionally accepts company_key and payment_status. |
| List Sales Cycle Stages | `listSalesCycleStages` | Vendor API (Basic auth). Returns the configured sales-cycle stages for leads or deals. Call this before createLead / updateLead (object_type lead, then use the stage api_name) or createDeal / updateDeal (object_type deal, then use the stage name) - writing a stage that is not in this list is rejected. Omit group_key for the company-wide stages. |
| List Tier Collections | `listTierCollections` | Vendor API (Basic auth). Returns every tier collection for your company. A collection is an ordered ladder of tiers plus the evaluation cycle that governs how often partners are re-tiered. Call this first to obtain the tier_collection_key that createTier requires. |
| List Tiers | `listTiers` | Vendor API (Basic auth). Returns the tiers in your program - the performance levels (Bronze, Silver, Gold) partners move between as they hit thresholds. Pass tier_collection_key to scope to one collection. Use the returned key as tier_key on updatePartnership. |
| List Transactions | `listTransactions` | Vendor API (Basic auth). Returns a cursor-paginated list of transactions, newest first. A transaction is a payment by a tracked customer and is what most reward rules are calculated from. Amounts are integer cents. Filter by customer (internal key, external key or email), product, category, or archived state. Also works with a Partner API key, returning only that partner's attributed transactions. |
| List Webhooks | `listWebhooks` | Vendor API (Basic auth). Returns the webhooks registered on your PartnerStack instance, each with its target_url and the event types it is subscribed to. Use it to confirm a registration landed or to find an orphaned endpoint. |
| Record Action | `recordAction` | Vendor API (Basic auth). Records an action taken by a partner or a customer - the hook for rewarding non-revenue behaviour such as completing a certification, booking a demo or activating a trial. target_type selects whether target_key is a partnership key or a customer key. value is how many times the action occurred. Reward rules configured in PartnerStack pick these up automatically. |
| Update Customer | `updateCustomer` | Vendor API (Basic auth). Updates a customer. Only the fields you send are changed; anything omitted is left alone. Note that changing customer_key rewrites the external key other systems address this customer by. |
| Update Deal | `updateDeal` | Vendor API (Basic auth). Updates a registered deal. Only the fields you send change. This is the write-back path from a CRM: move stage as the opportunity progresses, adjust amount and close_date, or set lost_reason when it is lost, and the partner sees it in their dashboard. stage must be a value from the group's Deal Stage list. |
| Update Lead | `updateLead` | Vendor API (Basic auth). Updates a lead. Only the fields you send change; anything omitted is left alone. This is how CRM status flows back to the partner: set status, or set stage_api_name to move the lead along your configured sales cycle, and the partner sees the progress in their dashboard. |
| Update Partnership | `updatePartnership` | Vendor API (Basic auth). Updates one partnership. Only the fields you send are changed. Use this to move a partner to another group or tier, reassign their partner manager, change their partner_key, or set custom field values. Tags are managed separately with updatePartnershipTags. |
| Update Partnership Tags | `updatePartnershipTags` | Vendor API (Basic auth). Adds and/or removes tags on one partnership. Send add, remove, or both. The response reports which tags were actually added, removed, and which could not be found. |
| Update Product | `updateProduct` | Vendor API (Basic auth). Updates a product instance. This is the endpoint to call on a plan change or a churn: set status to churned when the subscription ends, or adjust amount on an upgrade. Only the fields you send change. |
| Update Product Book | `updateProductBook` | Vendor API (Basic auth). Updates a product book's name or description. Only the fields you send change. The external_key cannot be changed here - it is set once at creation. |
| Update Tier | `updateTier` | Vendor API (Basic auth). Updates an existing tier. Only the fields you send change. Note that criteria and benefits are replaced wholesale, not merged - send the full list you want the tier to end up with. |
| Update Tier Collection | `updateTierCollection` | Vendor API (Basic auth). Updates a tier collection - rename it, activate or deactivate it, or set the evaluation cycle that decides how often partners are re-tiered. The cycle is a length plus a unit, with an optional delay before it starts and a repeat count. |
| Update Webhook | `updateWebhook` | Vendor API (Basic auth). Updates a registered webhook's target URL or its event subscriptions. events replaces the existing list wholesale rather than adding to it, so send the complete set you want the webhook to end up with. |

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Agreement accepted | `agreement.accepted` | A partner accepted the program terms of service. data carries the partnership plus the team member who accepted. |
| Application approved | `application.approved` | A partner application was approved. data is the application object with approved true. |
| Application created | `application.created` | A new partner application was submitted. data is the application object; content holds the submitted form fields. |
| Application declined | `application.declined` | A partner application was declined. data is the application object with approved false and a decline_reason. |
| Customer created | `customer.created` | A referred customer signup was tracked. data is the full customer object, matching what getCustomer returns. |
| Customer deleted | `customer.deleted` | A tracked customer was archived or deleted. data is the customer object as it was removed. |
| Customer updated | `customer.updated` | A tracked customer's name, email or provider key changed. data is the full customer object. |
| Deal created | `deal.created` | A partner registered a new deal. data is the deal object; amount is in CENTS and close_date is a date string. |
| Deal updated | `deal.updated` | A registered deal changed stage, amount or close date. data is the deal object. |
| Lead created | `lead.created` | A partner submitted a new lead. data is the lead object; meta holds the prospect details and amount is in CENTS. |
| Lead updated | `lead.updated` | An existing lead changed status or stage. data is the lead object. |
| Message created | `message.created` | A partner sent a message. Messages from the same sender within two minutes are bundled into one event. |
| Partner team member added | `partner_team.member_created` | Someone was added to a partner's team. data is the team member object. |
| Partner team member removed | `partner_team.member_removed` | Someone was removed from a partner's team. data is the team member object as removed. |
| Partnership agreement created | `partnership.agreement_created` | An agreement was issued to a partner for acceptance. data is the partnership the agreement belongs to. |
| Partnership archived | `partnership.archived` | A partner was archived and removed from the program. data is the partnership object as archived. |
| Partnership created | `partnership.created` | A new partner joined your program. data is the full partnership object. |
| Partnership tags updated | `partnership.tags_updated` | Tags were added to or removed from a partner. data is the full partnership object with its new tags. |
| Partnership updated | `partnership.updated` | A partner's key, group, tier or profile changed. data is the full partnership object. |
| Report export completed | `vendor_report_export.completed` | An export queued by exportCustomReport or exportBaseRecords finished. data carries the download URL, which expires. |
| Training course completed | `training.course_completed` | A partner finished a training course. data identifies the partner who completed it. |
| Training learning path completed | `training.learning_path_completed` | A partner finished a whole learning path. data identifies the partner who completed it. |
| Transaction created | `transaction.created` | A payment by a tracked customer was recorded. data is the transaction object; amount is in CENTS. |
