# Abyssale

<img src="../../.gitbook/assets/connectors/lg/abyssale.png" alt="Abyssale logo">

Abyssale image, video and PDF generation API. Generate banners and visuals from designs (synchronously or asynchronously), manage projects and workspace templates, import designs from JSON, list fonts, read credit balances, and manage the webhook signing secret.

| | |
| --- | --- |
| **Category** | [Marketing](README.md) |
| **Website** | [abyssale.com](https://abyssale.com) |
| **Authentication** | API key |
| **Slug** | `abyssale` |

## Use it

Add Abyssale from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.abyssale.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Check Service Health | `checkServiceHealth` | Liveness probe for the Abyssale API. Returns the plain-text body 'healthy'. Unlike every other route it needs no API key at all, so it reports only that the service is reachable - it says nothing about whether a key is valid. Undocumented: the route is live and proven to exist but is absent from Abyssale's published OpenAPI reference. |
| Check Service Readiness | `checkServiceReadiness` | Service health check for the Abyssale API. Returns the plain-text body 'healthy' when the API is reachable. This route is exempt from API-key validation but still requires an x-api-key header to be present, so it is useful for confirming connectivity and header wiring - never for testing whether a key is valid (use Verify API Key for that). |
| Create Design From JSON | `createDesignImport` | Import a design described as JSON. static, printer and animated designs carry formats plus top-level layers; a printer_multipage design carries a top-level pages array instead. Returns the import id, its status and an uploads array of presigned S3 POSTs, one per asset given as a bare filename. Set validate_only=true to validate without creating anything - it answers 204 No Content. Note: the API exposes no route for deleting a design. |
| Create Dynamic Image URL | `createDynamicImageUrl` | Create a dynamic image URL for a design. The returned img.abyssale.com URL renders the design on demand from query-string overrides, so a page can embed a personalised image without calling the generation API. One URL is returned per format. Answers 201 Created. The URL is public and unauthenticated, and each render consumes a generation credit - use enable_rate_limit to cap that. |
| Create Project | `createProject` | Create a new project in the connected Abyssale workspace. Projects group designs, and only designs inside a project are reachable through the API. Returns the created project's id and name. Note: the Abyssale API exposes no route for deleting a project, so a project created here can only be removed from the Abyssale web app. |
| Duplicate Workspace Template Into Project | `duplicateWorkspaceTemplate` | Copy a template from the workspace template library into a project as a new design. Duplication runs asynchronously: this returns a duplication request id to poll with Get Template Duplication Request Status. Note: the Abyssale API exposes no route for deleting a design, so the duplicate can only be removed from the Abyssale web app. |
| Export Design As Import Payload | `getDesignAsImport` | Export an existing design as a design-import JSON payload, ready to be fed back to Create Design From JSON. Returns the payload together with any conversion warnings and the payload contract version. Use it to clone, version-control or template an existing design. |
| Export Generated Assets As ZIP | `exportBanners` | Queue a ZIP archive of already-generated files, identified by their ids. Returns an export_id; supply callback_url to receive a NEW_EXPORT webhook carrying the archive's public URL when it is ready. The NEW_EXPORT callback has no subscription behind it, so a delivery that exhausts its retries is simply dropped. |
| Generate Image Synchronously | `generateImage` | Generate a single image from one format of a design and return the finished file in the response. Override any layer through elements, keyed by layer name - on this synchronous endpoint every value must be an object, a bare string answers 400 invalid_payload. Consumes one generation credit per render. For several formats at once use Generate Multiple Formats Asynchronously. |
| Generate Multi-Page PDF | `generateMultiPagePdf` | Queue generation of a multi-page PDF from a printer_multipage design. Content is addressed per page rather than per format, so pages is required. Returns a generation_request_id to poll with Get Generation Request Status, or supply callback_url for a NEW_BANNER_BATCH webhook. Consumes generation credits. Do not set original_visual_id - visual versioning is not wired on this endpoint. |
| Generate Multiple Formats Asynchronously | `generateMultiFormatMedia` | Queue generation of one or many formats of a design - images, animated GIF/MP4/HTML5 or print PDF. Returns a generation_request_id to poll with Get Generation Request Status, or supply callback_url to receive a NEW_BANNER_BATCH webhook when the batch is done. Consumes one generation credit per rendered format. image_file_type must match the design type or the request answers 400 invalid_filetype. |
| Get Credit Balance | `getCredits` | Get the remaining generation credits and AI credits for the connected workspace for the current billing period. Generation credits cover image, video, PDF and HTML5 renders; AI credits cover AI features such as text-to-image and background removal. Each block reports available, limit, consumed and extra. |
| Get Design Details | `getDesign` | Get the full details of one design by its UUID: name, type, project, its formats and its layer/property set. Pass i=advanced to receive the design's full layer set including group layers. A designId that is not a UUID does not match the route and answers 404. |
| Get Design Format Details | `getDesignFormat` | Get the details of one format of a design - its dimensions and the elements it contains. Identify the format by its name or, preferably, its UID, which survives a rename. Not applicable to printer_multipage designs, which have no formats. |
| Get Design Import Status | `getDesignImport` | Get one design-import job by its id: its effective status, any warnings, and the design it produced once it is DONE. An import whose presigned upload window closed before validation reports FAILED. |
| Get Generated File | `getFile` | Get one previously generated file (banner, video, PDF or HTML5 zip) by its UUID. Returns the file type and its download and CDN URLs, plus the format and the design it came from. The bannerId must be a UUID; any other shape does not match the route and answers 404. |
| Get Generation Request Status | `getGenerationRequest` | Poll an asynchronous generation request by id. Answers 202 Accepted with is_finalized false while the batch is still running, and 200 with is_finalized true and the generated files once it is done. Use it instead of, or alongside, the NEW_BANNER_BATCH webhook. There is no completion bound, so poll rather than waiting a fixed time. |
| Get Template Details | `getTemplate` | Get one template by UUID through Abyssale's legacy template route, the predecessor of Get Design Details. Live and proven to exist but absent from Abyssale's published OpenAPI reference; prefer Get Design Details for new work. |
| Get Template Duplication Request Status | `getDuplicationRequest` | Poll the status of a workspace-template duplication started by Duplicate Workspace Template Into Project. Returns the request's status and, once it has completed, the id of the design that was created in the target project. |
| Get Webhook Signing Secret | `getSigningSecret` | Retrieve the workspace's webhook signing secret, used to verify the X-Abyssale-Signature header. One secret covers every webhook in the workspace. Caution, this is not a pure read: the secret is created on the first call, and its existence is what switches webhook signing on for the whole workspace. The response contains the secret in plaintext. |
| List Design Imports | `listDesignImports` | List design-import jobs, optionally narrowed by effective status or creation window. Documented by Abyssale as GET /designs/import/json, but that route is not implemented on the live API: it answers 404 endpoint_not_found with a valid key. Built for completeness; expect it to start working only when Abyssale ships the route. |
| List Designs | `listDesigns` | List all designs (templates) in the connected Abyssale workspace, optionally filtered by project or design type. Only designs that live in a project are reachable through the API. Returns an array of design summaries with id, name, type, formats and project. |
| List Fonts | `listFonts` | List the fonts available to the connected workspace - Google fonts and fonts uploaded to the workspace. Filter to one family with the type parameter; an unknown value is ignored and the full unfiltered list is returned. Use the returned font names when overriding text layers during generation. |
| List Generated Files | `listGeneratedFiles` | List the generated files (banners, videos, PDFs and HTML5 archives) in the connected workspace. Undocumented companion of Get Generated File - the route is live and proven to exist, but it is absent from Abyssale's published OpenAPI reference, so its response shape may change without notice. |
| List Projects | `listProjects` | List every project in the connected Abyssale workspace. Projects group designs; only designs that belong to a project are reachable through the API. Returns each project's id, name and creation timestamp. |
| List Projects (Legacy Categories Route) | `listCategories` | List the workspace's projects through Abyssale's legacy categories route. Verified live to return exactly the same rows as List Projects - in the older vocabulary a project was called a category, and design responses still carry both category_id and project_id for the same value. The route is live and proven to exist but is absent from Abyssale's published OpenAPI reference; prefer List Projects for new work. |
| List Templates | `listTemplates` | List the workspace's templates through Abyssale's legacy template route, the predecessor of List Designs. The route is live and proven to exist but is absent from Abyssale's published OpenAPI reference; prefer List Designs for new work and use this only when a legacy integration depends on the older shape. |
| List Workspace Template Categories | `listWorkspaceTemplateCategories` | List the categories used to organise the workspace template library. Returns each category's id and name; feed an id to List Workspace Templates as category_id to narrow that listing. |
| List Workspace Templates | `listWorkspaceTemplates` | List the templates in the workspace template library, optionally filtered by category or design type. These are reusable starting points that Duplicate Workspace Template Into Project copies into a project as a new design. An unknown type value is ignored and the full unfiltered list is returned. |
| Revoke Previous Signing Secret | `revokeSigningSecret` | End a signing-secret rotation overlap early, revoking the previous secret immediately so only the current one verifies. Deliveries already in flight may still carry a signature from the revoked secret for up to a minute. Revoking also mints a secret, and so switches signing on, if none existed. |
| Rotate Webhook Signing Secret | `rotateSigningSecret` | Mint a new webhook signing secret for the workspace. The previous secret stays valid for a short overlap so in-flight deliveries still verify; the response reports when it expires. Answers 409 if a rotation is already in progress - pass force=true to rotate anyway and revoke the previous secret immediately. Rotating also mints a secret, and so switches signing on, if none existed. |
| Validate And Queue Design Import | `validateDesignImport` | Confirm that every presigned asset upload for an import has been completed, then validate the import and queue it for processing. Call it after uploading each file returned in the import's uploads array. An import with uploads still missing, or whose upload window has expired, is reported as failed. |
| Verify API Key | `verifyApiKey` | Check that the connected Abyssale API key is usable and find out which workspace it belongs to. Returns 200 with the workspace (company) name only if the key exists, is still active and, for a workspace key, the plan includes API access. Every failure is a 401: id 'unauthorized' for an unknown or revoked key, id 'api_access_denied' when the plan excludes API access. Takes no request body. |

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Batch Generation Completed | `NEW_BANNER_BATCH` | An asynchronous generation batch finished. Delivered either to a dashboard webhook or to the callback_url supplied on Generate Multiple Formats Asynchronously or Generate Multi-Page PDF. REGISTRATION FOR THE WORKSPACE-WIDE VERSION IS MANUAL: Abyssale web app &gt; Settings &gt; Webhooks &gt; Add a webhook, paste the fastn trigger URL, tick 'New banner batch' and save. For a single job instead, pass the fastn trigger URL as callback_url on the generation action. Payload schema modelled from Abyssale's published x-webhooks contract, not captured from a live delivery. |
| Design Status Changed | `TEMPLATE_STATUS` | A design's review workflow status changed - for example it moved to IN_REVIEW or APPROVED. Workspace-wide only. REGISTRATION IS MANUAL: Abyssale web app &gt; Settings &gt; Webhooks &gt; Add a webhook, paste the fastn trigger URL, tick the design/template status event and save. Payload schema modelled from Abyssale's published x-webhooks contract, not captured from a live delivery. |
| Export Archive Ready | `NEW_EXPORT` | A ZIP export requested with Export Generated Assets As ZIP is ready to download. Delivered only to the callback_url passed on that action - there is no dashboard subscription behind it, so nothing can be deactivated and a delivery that exhausts its retries is simply dropped. Its retry ladder starts at 60 seconds rather than 15. To use it, pass the fastn trigger URL as callback_url on Export Generated Assets As ZIP. Payload schema modelled from Abyssale's published x-webhooks contract, not captured from a live delivery. |
| File Generated | `NEW_BANNER` | A visual was generated in the workspace, including work started outside the API. This event has no per-job callback_url of its own - it only ever comes from a dashboard webhook. REGISTRATION IS MANUAL, there is no webhook CRUD API: in the Abyssale web app go to Settings &gt; Webhooks &gt; Add a webhook, paste the fastn trigger URL, tick the 'New banner' event and save. Verify deliveries with the X-Abyssale-Signature header (hex HMAC-SHA256 over 'v1:webhook:' + t + '.' + raw body) using the secret from Get Webhook Signing Secret, and deduplicate on X-Abyssale-Delivery-Id. Acknowledge with 200 or 201 within 15 seconds. Payload schema modelled from Abyssale's published x-webhooks contract, not captured from a live delivery. |
