# Remarkety

Remarkety is an eCommerce email and SMS marketing automation platform. This connector wraps the store-scoped Remarkety REST API (https://app.remarkety.com/api/v2/stores/{storeId}) covering customers, contacts, products, orders, segments, campaigns, email senders, templates, recommendations, sync status and outbound webhook subscriptions, plus the Remarkety event ingestion endpoints on webhooks.remarkety.com.

## Use it

Add Remarkety from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.remarkety.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Batch Upsert Contacts | `batchUpsertContacts` | Uploads up to 100 marketing contacts in one call. Returns {success, failed, failedReason:[{email, reason}]} so partially rejected batches can be repaired. Use update_existing to control whether known contacts are refreshed, and append_tags to add tags instead of replacing them. |
| Create Campaign | `createCampaign` | Creates a campaign from one of the types returned by List Campaign Types. The vendor's JSON schema for this route is strict and accepts EXACTLY three top-level fields - type, actions and mode - and rejects any other key with "The property X is not defined and the definition does not allow additional properties". type is the documented campaign type code such as TRIGGER_CART_RECOVERY; actions is an array of step objects each carrying a type of 'email' or 'api' plus that step's settings (email: subject + baseTemplate; api: webhook); mode is run, test or stop. CAUTION: mode 'run' activates the campaign and starts sending real email or SMS, and 'test' sends a test message - use 'stop' to create it inactive. A store with no verified sender or saved template answers 400 "Error creating campaign" after the schema passes. |
| Create Customer | `createCustomer` | Creates an eCommerce customer (shopper) in the connected Remarkety store. The payload must be wrapped in a 'customer' object. Returns {customer:{hash,...}} - keep the hash to read or update the record later. Note Remarkety has no customer delete endpoint. |
| Create Email Template | `createEmailTemplate` | Creates a master email template in the connected Remarkety store, using raw HTML (Editor Type html-code) or the Beefree drag-and-drop editor (Editor Type beefree-v1). Remarkety's API cannot delete templates; remove unwanted ones in the Remarkety app. |
| Create Or Update Contact | `createOrUpdateContact` | Creates a marketing contact in the connected Remarkety store, or updates it if the email / SMS number already exists. Either email or sms_phone_number is required. Set doubleOptin=false to skip the confirmation email. Returns {status:"OK", info:{...}} echoing the accepted fields. |
| Create Segment | `createSegment` | Creates a custom audience segment. Only name is required; conditions may be supplied to filter the audience. Returns the full new segment including its numeric id. Returns 409 when a segment with the same name already exists. |
| Create Sender | `createSender` | Adds a from-address (sender) to the connected store. 'name' is required. NOTE: this endpoint answers HTTP 200 for both outcomes - check the body, which is {"status":"success","message":"Sender has been created"} or {"status":"error","message":"..."}. Supplying an email address makes Remarkety mail a verification code to it. |
| Delete Campaign | `deleteCampaign` | Deletes a campaign by numeric id. VENDOR LIMITATION: Remarkety answers 400 {"message":"Not implemented"} - campaign deletion is not available over the API; pause a campaign with Update Campaign mode='stop' instead. Included because the route exists and may be enabled later. |
| Delete Customer | `deleteCustomer` | Deletes an eCommerce customer (shopper) by shopper hash. VENDOR LIMITATION: the route is routed but Remarkety answers 400 {"message":"Not implemented"} - customer deletion is not currently available over the API. Included for completeness and forward compatibility. |
| Delete Product | `deleteProduct` | Removes a product from Remarkety's copy of the store catalogue by its NUMERIC Remarkety product id (the 'id' field from List Products). The route matches digits only. Returns 404 {"message":"Product not found"} when the id is unknown. |
| Delete Segment | `deleteSegment` | Permanently deletes an audience segment by numeric segment id. Campaigns still targeting the segment will lose their audience, so check campaignsCount on the segment first. Returns 404 {"message":"Segment does not exists"} for an unknown id. |
| Delete Sender | `deleteSender` | Removes a sender (from-address) from the connected store by numeric sender id. Campaigns still using it will need a new From address. Returns 404 {"message":"Not Found"} for an unknown id. |
| Get Background Job | `getBackgroundJob` | Fetches one background job by id to check its progress or failure reason. ACCESS NOTE: entitlement-gated in the same way as List Background Jobs - a standard store API token receives 403 {"message":"Unauthorized Required"}. |
| Get Campaign | `getCampaign` | Fetches one campaign by numeric id. VENDOR LIMITATION: Remarkety answers 400 {"message":"Not implemented"} on this route today - read campaigns through List Campaigns or List Campaigns For Table. Included because the route exists and may be enabled later. |
| Get Campaign Group | `getCampaignGroup` | Fetches one campaign group by id. VENDOR LIMITATION: Remarkety currently answers 400 {"message":"Not implemented"} on this route - use List Campaign Groups. Included because the route exists and may be enabled later. |
| Get Campaign Stats | `getCampaignStats` | Returns the send, delivery, open, click, unsubscribe and revenue statistics for one campaign, by numeric campaign id. Returns 404 {"message":"Not Found"} for an unknown id. |
| Get Customer | `getCustomer` | Fetches one eCommerce customer (shopper) by its Remarkety shopper hash. Returns {customer:{...}} with email, name, tags, opt-in/suppression status, order counts and spend totals. Returns 404 'Shopper {hash} not found' when the hash is unknown. |
| Get Default Sender | `getDefaultSender` | Returns the store's default from-address, the one campaigns use when no sender is chosen explicitly. Answers HTTP 200 with {"status":"error","message":"sender not found"} when the store has no senders configured yet - check the body, not only the status. |
| Get Email Template | `getEmailTemplate` | Fetches one email template by id, including its stored HTML. Returns 404 {"message":"Not Found"} for an unknown id. |
| Get Order | `getOrder` | Fetches a single order by the store's own order id. The route matches digits only, so it works for stores whose order ids are numeric; a non-numeric order id falls through to Remarkety's HTML error page instead of the JSON API, and for those stores Search Orders is the way to read an order. Returns 400 {"code":"ORDER_NOT_FOUND"} when no such order is in Remarkety. |
| Get Product | `getProduct` | Fetches one catalogue product by its NUMERIC Remarkety product id - the 'id' field from List Products, not the store's own storeProductId. The route matches digits only: a non-numeric id falls through to Remarkety's HTML error page instead of the JSON API. Returns 404 {"message":"Product not found"} for an unknown numeric id. |
| Get Segment | `getSegment` | Fetches one audience segment by its numeric Remarkety id, including its conditions, current size and when it was last calculated. Returns 404 {"message":"Segment does not exists"} for an unknown id. |
| Get Segment Preview Size | `getSegmentPreviewSize` | Returns {count:N} - how many contacts a segment definition would currently match, without saving a segment. This GET form takes its filter on the query string; use Preview Segment Conditions to pass a structured condition set in the body. |
| Get Sender | `getSender` | Fetches one sender (from-address) by numeric id, returning {id, name, from_name, from_email, is_verified, is_default}. Returns 404 {"message":"Not Found"} for an unknown id. |
| Get Store Event | `getWebhookSubscriptionByEvent` | Returns the full recorded payload of one store event by its event_id from List Store Event Log - for an unsubscribe that is the ip, useragent, source and email; for an order or product event it is the ingested record. Returns 404 {"message":"Event doesn't exists"} for an unknown id. Use it to inspect exactly what Remarkety stored for an event. |
| Get Store Sync Status | `getStoreSyncStatus` | Returns the Remarkety data-sync health for the connected store: syncStatus, lastSyncSuccess, lastSyncAttempt and syncLastError. Takes no input and is the cheapest read for verifying that the API token and store ID are valid. |
| List Background Jobs | `listBackgroundJobs` | Lists the store's background jobs (imports, syncs, exports). ACCESS NOTE: this route is entitlement-gated - a standard store API token receives 403 {"message":"Unauthorized Required"}; elevated access must be granted by Remarkety. |
| List Campaign Groups | `listCampaignGroups` | Returns the campaign groups (multi-step flows) defined in the connected store. A group bundles several campaigns that run as one sequence, and its name appears as campaign_group on outbound webhook events. |
| List Campaign Performance Stats | `listCampaignPerformanceStats` | Returns send/open/click/revenue performance figures across all campaigns in the connected store, as an array of per-campaign stat rows. Use Get Campaign Stats for a single campaign. |
| List Campaign Types | `listCampaignTypes` | Returns the campaign templates Remarkety offers, as {public:{...}, private:[...]}. Each entry gives the numeric id, display name, uniqueName (e.g. abandoned_cart, simple_newsletter, happy_birthday), whether it is transactional and whether it is active. The uniqueName is the value Create Campaign expects in its 'type' field. |
| List Campaigns | `listCampaigns` | Returns the marketing campaigns configured in the connected Remarkety store as a plain array. Use List Campaigns For Table when you need the paged, DataTables-shaped view with record counts. |
| List Campaigns For Table | `listCampaignsForTable` | Paged campaign listing shaped for a data grid: returns {data:[...], draw, recordsFiltered, recordsTotal}. Use recordsTotal to drive paging; use List Campaigns for the plain array form. |
| List Contacts | `listContacts` | Collection read on the contacts resource. VENDOR LIMITATION: Remarkety answers 400 {"code":"NOT IMPLEMENTED"} - a plain contact list is not exposed. Use Search Contacts instead. Included because the route exists and may be enabled later. |
| List Customers | `listCustomers` | Lists the eCommerce customers (shoppers) known to the connected Remarkety store. Returns {customers:[...]} where each entry carries the Remarkety shopper hash, email, tags, opt-in status, suppression flag and order totals. Use the hash with Get Customer / Update Customer. |
| List Email Templates | `listEmailTemplates` | Returns the email templates saved in the connected Remarkety store, as an array. Template ids from here are what campaign email steps reference. |
| List Product Recommendations | `listProductRecommendations` | Returns the product recommendation blocks Remarkety has computed for the connected store, used to personalise campaign content. Returns an empty array until the store has enough catalogue and order history. |
| List Products | `listProducts` | Returns the product catalogue Remarkety holds for the connected store, as an array of product records. Products reach Remarkety through the platform plugin or a Google Product Feed, so this endpoint is read-only: the /products collection ignores the HTTP verb and always returns the list. |
| List Segments | `listSegments` | Lists the audience segments defined in the connected Remarkety store. Returns {data:[{id,name,description,conditions,currentSize,lastCalculatedOn,campaignsCount,type,...}]}. |
| List Segments Of A Customer | `listCustomerSegments` | Returns {segments:[...]} - the Remarkety segments the given customer (shopper hash) currently belongs to. Useful for checking why a contact is or is not receiving a segment-targeted campaign. |
| List Senders | `listSenders` | Returns the from-addresses configured for the connected store: [{id, name, from_name, from_email, is_verified, is_default}]. Only verified senders can be used as the From address on a campaign. |
| List Store Event Log | `listWebhookSubscriptions` | Returns the connected store's recent event log - every event Remarkety received or raised, newest first: [{event_time, store_event_type, event_id, info}]. store_event_type covers the ingestion topics (customers/update, orders/create, products/create) and Remarkety's own topics (newsletter/unsubscribed). Pass an event_id to Get Store Event for the full payload. This is the audit trail for Send Store Event and the way to confirm an event was accepted and parsed - an event Remarkety could not read shows info "Event parsing error". Read-only: POST, PUT and PATCH on this route answer 400 "Not implemented". |
| Preview Campaign Content | `previewCampaignContent` | Renders the email body a campaign would send, for review before activating it. ACCESS NOTE: this route is entitlement-gated - accounts without preview rights receive 403 {"message":"Unauthorized Required"} even with a valid API token. |
| Preview Segment Conditions | `previewSegmentConditions` | Sizes a candidate segment before creating it: POST a condition set and Remarkety returns {count:N}, the number of contacts that would match. Use this to validate targeting before Create Segment. |
| Query Campaign Performance Stats | `queryCampaignPerformanceStats` | POST variant of the cross-campaign performance report, taking the reporting window and any grouping options in the request body rather than the query string. Returns the same array of per-campaign stat rows. |
| Search Contacts | `searchContacts` | Returns the store's marketing contacts as a flat array with email, first/last name, order counts, total and average spend, currency, tags and engagement fields. VENDOR BEHAVIOUR: 'limit' is honoured but 'email' is NOT - the endpoint returns the store's contacts regardless of the email supplied, so filter the returned rows yourself. This is the read counterpart to Create Or Update Contact; Remarkety exposes no plain /contacts list. |
| Search Contacts By Criteria | `searchContactsByCriteria` | POST variant of the contact search, taking criteria in the request body rather than the query string. VENDOR BEHAVIOUR: neither the email filter nor limit is honoured on this form - it returns the store's full contact list, so filter and page the rows yourself. Returns the same contact row shape as Search Contacts. |
| Search Orders | `searchOrders` | Searches the orders Remarkety holds for the connected store and returns them as an array. Filters are supplied on the query string (email, date range, paging). Remarkety exposes no plain /orders collection - this is the way to enumerate orders. |
| Search Orders By Criteria | `searchOrdersByCriteria` | POST variant of the order search, taking structured filter criteria in the request body instead of the query string. Returns the same array of order records as Search Orders. |
| Send Store Event | `sendStoreEvent` | Pushes an eCommerce event into Remarkety's ingestion endpoint so automations can react and customer/order/product/cart data stays current. eventType is one of customers/create, customers/update, orders/create, orders/update, products/create, products/update, products/delete, carts/create, carts/update, newsletter/subscribe, newsletter/unsubscribe, or a custom type. Returns the plain text OK on success. The remaining fields are the event subject and vary by eventType. |
| Send Store Event To Store Path | `sendStoreEventToStorePath` | Same event ingestion as Send Store Event, but posting to Remarkety's path-addressed ingestion route /webhooks/store/{storeId} rather than the ?storeId= query form. Remarkety documents this form for browser-side tracking calls; use it when a gateway strips query strings. Returns the plain text OK. |
| Unsubscribe Contact | `unsubscribeContact` | Unsubscribes a contact from email and/or SMS marketing. Supply email, sms_phone_number_e164, or both; an optional reason is stored with the suppression. Returns {status:"OK", info:{email, sms_phone_number_e164}}. |
| Update Campaign | `updateCampaign` | Updates an existing campaign by numeric id. NOTE: the update route uses a DIFFERENT mode vocabulary from Create Campaign - here mode is one of running, testing, stopped or archived (Create Campaign uses run/test/stop). CAUTION: 'running' activates the campaign and starts sending real email or SMS and 'testing' sends a test message; use 'stopped' to pause or 'archived' to retire it. The body is validated before the campaign id is resolved. |
| Update Customer | `updateCustomer` | Updates an existing eCommerce customer (shopper) identified by its Remarkety shopper hash. The payload must be wrapped in a 'customer' object. Returns the full updated {customer:{...}} record. |
| Update Email Template | `updateEmailTemplate` | Updates an existing email template by id - its name, subject or HTML body. Returns 404 {"message":"Not Found"} for an unknown id. Changes take effect for any campaign step referencing the template. |
| Update Product | `updateProduct` | PUT on a catalogue product by its NUMERIC Remarkety product id (the 'id' field from List Products). VENDOR BEHAVIOUR: this route answers 200 with the product record but does NOT apply the body - a follow-up Get Product shows the product unchanged, for every field shape tried. Use Send Store Event with eventType products/update to actually change a product in Remarkety. Returns 404 {"message":"Product not found"} for an unknown numeric id. |
| Update Segment | `updateSegment` | Renames an audience segment or replaces its filter conditions, by numeric segment id. Returns the full updated segment record. Returns 404 {"message":"Segment does not exists"} for an unknown id. |
| Update Sender | `updateSender` | Renames a sender (from-address) or changes its from_name, by numeric sender id. Returns {"status":"success","message":"Sender has been updated"}. Returns 404 {"message":"Not Found"} for an unknown id. |
| Verify Sender Address | `verifySenderAddress` | Completes verification of a sender from-address by submitting the code Remarkety emailed to it. Answers HTTP 200 for both outcomes - read the body: a missing code gives {"status":"error","message":"Empty verification code"} and a wrong code gives {"status":"error"}. The code can only be obtained from the sender's own mailbox. |

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Email Bounced | `email/bounced` | A campaign email bounced. Use it to keep your own suppression list in step with Remarkety's. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| Email Delivered | `email/delivered` | The receiving mail server accepted a campaign email. Registration is UI-only - see Email Sent for the click-path: app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. Topic arrives in the X-Event-Topic header and the body is signed with X-Event-Hmac-SHA256. |
| Email Link Clicked | `email/clicked` | A recipient clicked a link in a campaign email; link_url is the destination. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| Email Marked As Spam | `email/spam` | A recipient reported a campaign email as spam. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| Email Opened | `email/opened` | A recipient opened a campaign email. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. Carries the recipient's user agent and IP as reported by their mail client. |
| Email Sent | `email/sent` | Remarkety sent a campaign email to a recipient. REGISTRATION IS UI-ONLY: the Remarkety API answers 400 "Not implemented" to POST/PUT/PATCH on /webhooks, so a human must register the endpoint once - sign in at https://app.remarkety.com, open the store, go to Settings -&gt; Integrations, find the Webhooks / JSON webhooks section, paste the fastn webhook URL into the endpoint field, save, and copy the Shared Secret shown there. Remarkety then POSTs each event with headers X-Event-Topic (the topic, e.g. email/sent) and X-Event-Hmac-SHA256 (base64 HMAC-SHA256 of the raw body using that Shared Secret). Your endpoint must answer 2xx within 5 seconds; Remarkety retries at growing intervals for 2 hours, then emails the account administrator. |
| Email Suppression Added | `email-suppression/added` | An address was added to the store's email suppression list. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| Email Suppression Removed | `email-suppression/removed` | An address was removed from the store's email suppression list. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| Email Unsubscribed | `email/unsubscribed` | A recipient unsubscribed from email marketing through a campaign email. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| Newsletter Subscribed | `newsletter/subscribed` | Someone signed up for the store's newsletter, with the sign-up and opt-in IPs and any captured properties. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| SMS Link Clicked | `sms/clicked` | A recipient clicked a link in a campaign SMS. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| SMS Replied | `sms/replied` | A recipient replied to a campaign SMS; the reply text is in the payload. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| SMS Sent | `sms/sent` | Remarkety sent a campaign SMS to a recipient. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
| SMS Unsubscribed | `sms/unsubscribed` | A recipient opted out of SMS marketing. Registration is UI-only - app.remarkety.com -&gt; Settings -&gt; Integrations -&gt; Webhooks, paste the fastn webhook URL, save, copy the Shared Secret. |
