# Orshot

<img src="../../.gitbook/assets/connectors/lg/orshot.png" alt="Orshot logo">

This connector wraps the Orshot v1 REST API: studio and library (utility) template rendering, signed render URLs, async render jobs, brand assets (images, videos, audio, colors, fonts), template folders, sharing and versions, AI video generation, social publishing and analytics, workflows, and workspace profile and logs.

| | |
| --- | --- |
| **Category** | [Marketing](README.md) |
| **Website** | [orshot.com](https://orshot.com) |
| **Authentication** | Bearer token, OAuth 2.0 |
| **Slug** | `orshot` |

## Use it

Add Orshot from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.orshot.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Render Job Finished</td><td><code>render_job.finished</code></td><td>Fires when an asynchronous Orshot render job reaches a terminal status (succeeded or failed). Orshot has NO webhook subscription registry - there is no /v1/webhooks or /v1/events route (both return 404 route_not_found). Registration is PER REQUEST: copy this trigger's fastn webhook URL and pass it as the top-level `webhook_url` field of the render request that should notify you - either POST /v1/studio/render with response.mode set to "async" (action: Render From Studio Template), or POST /v1/ai/video (action: Generate AI Video). Optionally also pass a top-level `metadata` string, which Orshot echoes back inside job.metadata so you can correlate the delivery with your own record. The URL must be publicly reachable over http(s); private and loopback addresses are rejected at create time. Orshot attempts delivery 3 times (immediately, +30s, +2m) with a 10-second timeout each and treats any 2xx as an acknowledgement. Jobs you cancel do NOT fire; every other terminal status does. Webhooks are a convenience only - polling Get Render Job remains the vendor's source of truth.</td></tr></tbody></table>
