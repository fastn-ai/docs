# Whop

<img src="../../.gitbook/assets/connectors/lg/whop.png" alt="Whop logo">

Whop is a commerce platform for selling digital products, memberships and communities. This connector covers the Whop REST API v1 (both the Current versioned surface and the supported Legacy surface): accounts and companies, users and team members, products, plans and checkout configurations, memberships and members, payments, invoices, refunds, disputes and dispute alerts, resolution center cases, promo codes, payouts, transfers, ledgers and cards, experiences, courses, forums, chats and messages, reviews, entries, leads, affiliates, apps and app builds, files and media, notifications, exports, stats and webhooks.

## Use it

Add Whop from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.whop.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Accept Resolution Center Case | `acceptResolutionCenterCase` | Accepts the case in the customer's favour, as the merchant: refunds the payment in full and closes the case. This moves real money and cannot be undone. Check Available Actions on the case includes accept before calling. |
| Activate Experiment | `activateExperiment` | Starts or resumes an experiment or feature flag so evaluation begins serving it to real subjects. Activating a draft stamps started_at; resuming a paused experiment keeps the original start. Only drafts and paused experiments can be activated. |
| Activate Payment Rule | `activatePaymentRule` | Activates a payment rule so it starts applying to new payments again. Reversible with Deactivate Payment Rule. |
| Activate Promo Code | `activatePromoCode` | Turns an inactive promo code back on so it can be redeemed at checkout. Equivalent to Update Promo Code with Status set to active. |
| Add Free Days to Membership | `addFreeDaysMembership` | Adds free days to a membership, extending the billing period, the expiration date, or the Stripe trial depending on the plan type. Whop removed this route as of Api-Version-Date 2026-07-23, so this action pins 2026-07-22 — the last version that implements it — while every other Whop action uses 2026-09-15. On current API versions the supported route is Extend Membership; prefer that action unless you specifically need this legacy route. |
| Add People to Audience | `addAudiencePeople` | Adds people from a new CSV file to an existing uploaded custom audience, PUSHING THAT CUSTOMER DATA TO THE AD PLATFORM. The file is read using the audience's saved column mapping, so its headers must match. Processing happens in the background and existing members are left in place - this appends rather than replaces. |
| Appeal Resolution Center Case | `appealResolutionCenterCase` | Appeals a decision, as the customer, on a case that closed in the merchant's favour. This escalates the case to Whop for platform review. A case can be appealed once and only once, so it cannot be undone or repeated. |
| Approve Entry | `approveEntry` | Approves a pending waitlist entry, which TRIGGERS THE CHECKOUT PROCESS to grant the applicant access to the plan - on a paid plan that means the applicant is charged. The work runs asynchronously and the response is only a job id, not the finished entry, so poll Retrieve Entry to see the outcome. Needs plan:waitlist:manage. |
| Archive Affiliate | `archiveAffiliate` | Archives an affiliate so they stop earning new commission. Whop has no delete for affiliates, so this is how you retire one; it is reversible with Unarchive Affiliate. Returns the bare JSON boolean true on success; this route does not return an object, so read the affiliate back with List Affiliates filtered to archived if you need the updated record. Requires the affiliate:update permission. |
| Attach Experience to Product | `attachExperience` | Attaches an experience to a product, making it reachable by that product's customers. An experience can be attached to several products. Requires the experience:attach permission. |

* **Calculate Plan Tax** `calculatePlanTax`: Previews the tax on a plan before checkout, based on the buyer's billing address or IP address. Supply either an address with a country or an IP address.
* **Cancel Bounty** `cancelBounty`: Cancels a bounty and REFUNDS THE ESCROWED POOL to the funder. With no in-flight work it cancels immediately; otherwise it stops new submissions and cancels once the in-flight work resolves and pays out, with cancel_requested_at set meanwhile. Repeating the request is a no-op. A bounty that already paid out every slot returns 400.
* **Cancel Bounty Submission** `cancelBountySubmission`: Cancels the caller's own active attempt on a bounty and DISCARDS any accumulated capture clips, which cannot be recovered. Only the worker who started the attempt can cancel it; an account API key cannot.
* **Cancel Membership** `cancelMembership`: Cancels a membership. Pass Cancel At Period End as true to stop auto-renewal and keep access until the current billing period ends, or omit it to revoke access immediately.
* **Cancel Payout** `cancelPayout`: Cancels a payout that is still in review and returns the funds, fees included, to the balance. A payout can only be cancelled while its status is in_review: a requested payout is still being prepared and answers 409 until it reaches in_review, and anything further along cannot be stopped.
* **Capture Payment** `capturePayment`: Captures the full amount of a card payment that was created with Capture set to false. The payment must still be in requires_capture and before its Capture Expires At deadline. Partial capture, multiple captures, capturing more than the authorized amount, and tips are not supported. This moves real money.
* **Check User Access** `checkUserAccess`: Checks whether a user has access to an account, product or experience that the caller can reach, and at what level.
* **Complete File Multipart Upload** `completeFile`: Assembles the parts of a multipart upload once every part has been PUT to its presigned URL. Pass the multipart_upload_id from Create File and, for each part, the ETag that the part's own upload returned. Parts must be listed in order and none may be missing, or assembly fails.
* **Connect Social Account** `connectSocialAccount`: Starts an OAuth connection flow and returns an authorize_url for the user to open. Nothing is connected until a human completes that flow, so calling this has no side effect by itself. Use meta_business to connect Meta Business assets - that is how both Facebook pages and Instagram accounts are connected, and there is no separate instagram value.
* **Create Access Token** `createAccessToken`: Create a short-lived access token for authenticating API requests. When using API key authentication, provide account_id or user_id; when using OAuth the user is derived from the token. Use this token with Whop's web and mobile embedded components. The returned `token` is a live bearer credential - treat it as a secret and never log it.
* **Create Account** `createAccount`: Creates an account. User tokens create business accounts; Account API keys create connected accounts. Tax fields (`tax_remitted_by`, `tax_type`, `product_tax_code_id`, `business_address`, `tax_identifiers`) are configured with Update Account, not at creation.
* **Create Account Link** `createAccountLink`: Generate a URL that directs a sub-merchant to their account portal, such as the hosted payouts dashboard or the KYC onboarding flow. The returned URL embeds a signed session token - treat it as a secret and hand it only to the merchant it was minted for.
* **Create Ad** `createAd`: Creates an ad in an ad group, from uploaded creatives or an existing social post. Any campaign status other than draft launches the campaign, which requires an ads payment method on the account.
* **Create Ad Campaign** `createAdCampaign`: Creates an ad campaign for an account.
* **Create Ad Group** `createAdGroup`: Creates an ad group (ad set) in a campaign, with its targeting, budget, schedule and optimization settings.
* **Create Affiliate** `createAffiliate`: Creates an affiliate for an account and user, or returns the existing one if that user is already an affiliate, so it is safe to call repeatedly. There is no delete for affiliates — use Archive Affiliate to retire one. Requires the affiliate:create permission.
* **Create Affiliate Override** `createOverrideAffiliate`: Creates a commission override for an affiliate, replacing the account's default rate for them. A standard override pays commission on one plan and needs Plan ID. A rev-share override pays a share of revenue and takes an optional Product ID — omit it to cover the whole account. Requires the affiliate:create permission.
* **Create AI Chat** `createAiChat`: Creates an AI chat thread and sends the first message to the agent. This invokes a real, metered AI agent - the thread reports blended_token_usage. Agent Identifier defaults to support, which is Whop's own support agent, so leaving it unset starts a support conversation rather than a general one. Needs ai_chat:create.
* **Create API Key** `createApiKey`: Creates an API key for an account or app. The response is the only place the full secret key is ever returned, so store it immediately — it cannot be read back later, only rotated. Requires a whop.com user session: an API key cannot create API keys.
* **Create App** `createApp`: Registers a new app on the Whop developer platform. Apps provide the custom experiences that get added to products. Two things to know before calling: claiming a Route reserves that subdomain, and deleting the app later keeps it reserved for a month; and Whop also creates a backing product for the app, which Delete App does NOT remove, so delete that product separately if you do not want it left behind.
* **Create App Build** `createAppBuild`: Uploads a new build artifact for an app. Upload the file first with Create File or a direct upload, then reference it here: iOS and Android take a .zip bundle, web takes a JavaScript file or a .zip archive. A new build starts as a draft — promote it with Promote App Build.
* **Create Audience** `createAudience`: Creates an ad audience from an uploaded customer list, your account's Whop People data, or social engagement - or a lookalike from an existing audience. THIS PUSHES CUSTOMER IDENTITY DATA TO THE AD PLATFORM (Meta), so the resulting audience lives on their side as well as Whop's. Processing runs asynchronously: poll the audience's status. Creating a custom audience returns one audience; creating lookalikes returns the whole set in a data array.
* **Create Authorized User** `createAuthorizedUser`: Adds an authorized user to a company, GRANTING THEM REAL ACCESS at the role you choose - an admin can then act on the account. Send Emails notifies the person by email. Whop treats this as a sensitive action and may demand re-authentication proof in Elevation (a WebAuthn assertion, a TOTP code, or an emailed code). Note this is the legacy authorized-user surface; Create Team Member is the current equivalent and accepts more roles.
* **Create Bounty** `createBounty`: Creates a bounty and ESCROWS ITS REWARD POOL from the funding account's balance - this moves real money. The escrowed total is Gross Reward Amount times Accepted Submissions Limit and must be at least 5 USD. The bounty publishes immediately unless you set Publish At, which creates a hidden draft that is funded and published at that time instead.
* **Create Bounty Submission** `createBountySubmission`: Creates a submission on a bounty. Include a Deliverable - any combination of links and uploaded files, with at least one of the two - and the submission goes straight to review, making create the only step. For data_capture bounties omit the Deliverable instead: that starts a claimed attempt whose proof accumulates server-side, and Submit Bounty Submission sends it to review once complete. Requires a USER credential; an account API key cannot author submissions.
* **Create Card** `createCard`: Issues a virtual card, or files a card-issuing application. An account with no application on file gets a 202 here, meaning the application was filed rather than a card issued; call again once it is approved to actually issue the card. Both outcomes are real financial actions against the account. The issued card's response carries a secrets block with the full card number, CVC and PIN - handle it as cardholder data and do not log it.
* **Create Cashback Rule** `createCashbackRule`: Creates a future-dated card cashback rule funded by the authenticated platform account. Requires payout:transfer_funds. Both the raw merchant name and four-digit MCC are required. The funding account is derived from the credential and cannot be supplied. Creation does not transfer funds, but the rule WILL pay real cashback once it starts. NOTE the singular path /cashback_rule on create while every other route in this family is plural, and that THERE IS NO DELETE ROUTE - a created rule can only be narrowed with Update Cashback Rule (expires_at).
* **Create Checkout Configuration** `createCheckoutConfiguration`: Creates a reusable checkout configuration and returns the checkout URL customers open. Point it at an existing plan with Plan ID, or describe an inline Plan; the two are mutually exclusive.
* **Create Company Token Transaction** `createCompanyTokenTransaction`: Create a token transaction to add, subtract, or transfer company loyalty tokens for a member. This CHANGES a real member's token balance: an 'add' credits them and a 'subtract' debits them, and there is no delete route - reverse an add with a matching subtract. Required permissions: `company_token_transaction:create`, `member:basic:read`, `company:basic:read`.
* **Create Confirmation Token** `createConfirmationToken`: Mints a single-use, short-lived token from what a buyer entered on your collection surface - the payment method payload, billing details and attested save consent. THIS CARRIES REAL CARDHOLDER OR BANK DATA: it is meant to be called from the buyer's own surface, never from a server holding raw card numbers you have stored. The route is PUBLIC and rate-limited, and the account_id in the body scopes the token WITHOUT authenticating - so possessing an account id is not permission to act for that account. Confirm the token server-side with Create Payment.
* **Create Course** `createCourse`: Creates a course inside an experience. Whop seeds it with one chapter and one lesson, so a new course is never empty. Add more with Create Course Chapter and Create Course Lesson. Requires the courses:update permission.
* **Create Course Chapter** `createCourseChapter`: Creates a chapter in a course, to group lessons into sections. New chapters are appended after the existing ones; reorder them with Update Course. Requires the courses:update permission.
* **Create Course Lesson** `createCourseLesson`: Creates a lesson in a course chapter. A lesson can hold text, video, a PDF, or an assessment. Assessment questions and file attachments are added afterwards with Update Course Lesson. Requires the courses:update permission.
* **Create Deposit** `createDeposit`: Returns the deposit methods for an account - a hosted deposit URL plus the crypto deposit addresses and bank transfer details. It does NOT move money: amount only prefills the hosted page. Bitcoin deposits are converted by Relay directly to USDT on Plasma in the destination account's wallet. Crypto deposits require a $10 minimum.
* **Create DM Channel** `createDmChannel`: Creates a DM channel between two or more users, optionally scoped to a company, and returns the existing channel if one already exists rather than duplicating it. The other participants SEE THE CONVERSATION APPEAR, so treat this as contacting real people. Needs dms:channel:manage.
* **Create DM Member** `createDmMember`: Adds a user to an existing DM channel. The person gains access to the conversation and its history, so this exposes real content to a real person. Only a channel admin can add members. Needs dms:message:manage or support_chat:message:create.
* **Create Domain** `createDomain`: Creates an unverified domain claim and returns the DNS records to publish. A claim does NOT reserve the hostname globally. Once you publish the returned TXT record, ownership verification, DNS checks and certificate provisioning all run automatically. An unverified claim is deleted on its own after 48 hours. Set Replace Existing only when you deliberately intend to TAKE A DOMAIN AWAY from its current owner - that is a live traffic change for whoever holds it today.
* **Create Event** `createEvent`: Tracks a conversion or engagement event against an account. This WRITES ATTRIBUTION DATA about a real person - the user block carries identity and context carries IP address, device fingerprint and ad-network click ids - and Whop exposes no delete route for events, so what you send here is permanent. Pass Event ID to make a retry idempotent; without one, sending the same event twice records it twice and double-counts the conversion.
* **Create Experience** `createExperience`: Creates an experience on an account, powered by the app you name. Attach it to a product afterwards with Attach Experience so customers can reach it. Requires the experience:create permission.
* **Create Experiment** `createExperiment`: Creates a draft experiment, or a feature flag when Feature Flag Only is true. It starts in draft and serves nothing until Activate Experiment is called. Whop exposes no delete route for experiments, so anything created here is permanent - create deliberately. Pass internal as the Account ID for a Whop platform experiment.
* **Create Export** `createExport`: Starts an asynchronous export of a resource for an account. Returns the export in `pending`; poll Retrieve Export until `download_url` is set. There is no delete route - an export self-expires 30 days after creation.
* **Create Fee Markup** `createFeeMarkup`: Create or update a fee markup for a company. UPSERT: if a markup for the specified fee_type already exists it is updated in place and the same id is returned, so this is not safe to assume is a fresh create. Required permissions: `company:update_child_fees`.
* **Create File** `createFile`: Creates a file record and returns a presigned destination to upload the bytes to. PUT the bytes to upload_url for a single-part upload, or to each of multipart_upload_urls and then call Complete File Multipart Upload. The file becomes ready once the bytes land, and its id can then be attached wherever a file is accepted. Visibility defaults to private, which is the safe choice - public serves the file from an UNSIGNED CDN URL that anyone who has the link can read, so only choose it for assets meant to be world-readable. Whop exposes no delete route for files, so a record created here is permanent even if you never upload the bytes.
* **Create Forum Post** `createForumPost`: Creates a forum post, or a comment when Parent ID is set. Whop exposes NO delete route for forum posts, so anything created here is permanent and stays visible in the forum - post deliberately. Two inputs do something real on their own: Is Mention sends a notification to every user in the experience who has mentions enabled, and Paywall Amount with Paywall Currency turns the post into a paid unlock. Pass experience_id "public" together with Account ID to post to an account's public forum. Needs forum:post:create.
* **Create Invoice** `createInvoice`: Creates an invoice for a customer. The invoice can be charged automatically against a stored payment method, or sent to the customer for manual payment. Set Save As Draft to create it without sending or charging anything, which also relaxes the customer and due-date requirements. Requires invoice:create, member:basic:read, member:email:read and payment:basic:read.
* **Create Lead** `createLead`: Records a lead against a company, capturing a person's interest in a product. Whop exposes NO delete route for leads, so a lead recorded here is permanent. Note what happens when User ID is omitted: on a user credential Whop records THE AUTHENTICATED USER as the lead, so leaving it blank does something real rather than nothing. Needs lead:manage.
* **Create Message** `createMessage`: Sends a message in an experience chat, DM or group chat channel. THIS DELIVERS TO REAL PEOPLE - everyone in the channel sees it and may be notified. Supports Markdown content, file attachments, polls and threaded replies. Needs one of chat:message:create, dms:message:manage, livestream:chat:write or support_chat:message:create, depending on the channel.
* **Create OAuth Grant** `createOauthGrant`: Completes the OAuth authorization step for the authenticated user: records their consent for the scopes an app asked for and mints the authorization code to hand back to it. Returns the grant plus a Redirect URL carrying that code — the one and only time the code is returned. Exchange it at POST /oauth/token together with the verifier for Code Challenge. Requires a whop.com user session, because consent has to come from the account holder: an account API key or an OAuth token is refused, so an app can never authorize itself.
* **Create Passkey** `createPasskey`: Registers a passkey for the authenticated user from the attestation a browser produced for a registration challenge. Mint that challenge first with Create Passkey Challenge; it is single-use and expires five minutes after it is issued. Requires a whop.com user session.
* **Create Passkey Challenge** `createPasskeyChallenge`: Mints the challenge a browser needs to run a WebAuthn ceremony against the authenticated user's own passkeys. A registration challenge enrolls a new passkey; a deletion challenge is bound to the single passkey named by Passkey ID and proves the user still holds it. Challenges are single-use and expire five minutes after they are issued. Requires a whop.com user session.
* **Create Payment** `createPayment`: Charges a buyer for a plan. Pass a payment method already on file (Member ID plus Payment Method ID), or a Confirmation Token describing a method the buyer has just supplied. Collection runs in the background, so the response is the payment as created, not its outcome — poll Retrieve Payment Status for how far it has got and, for a confirmation-token payment, what the buyer must still do. Pass Plan ID for an existing plan, or Plan to find or create one inline. This charges real money.
* **Create Payment Method Domain** `createPaymentMethodDomain`: Registers a hostname with the wallet provider and attempts verification inline - this reaches out to the provider about a real domain, so only register hostnames you actually control. Returns status verified when the provider fetched the domain-association file (for Apple Pay that is /.well-known/apple-developer-merchantid-domain-association), or pending when it could not. On pending, host the file and then call Verify Payment Method Domain.
* **Create Payment Rule** `createPaymentRule`: Creates a payment rule. Every condition in Conditions must match for the Action to apply. What a rule does is fixed once created — use Replace Payment Rule to change its action or conditions, so the payments it already decided keep naming the rule that decided them. Build conditions from the vocabulary in List Payment Rule Fields.
* **Create Payout** `createPayout`: Sends money from an account or user balance to one of that owner's saved payout methods. This moves real funds. Balances are held per currency and the payout draws only from the balance in the currency you name. Where the ledger requires quoting, create a quote first with Create Payout Quote and pass its Quote Token here.
* **Create Payout Method** `createPayoutMethod`: Saves a new destination an account or user can pay out to. Sensitive details are vaulted in transit and never stored raw. Find the Supported Payout Method ID and the exact fields it needs with List Supported Payout Methods.
* **Create Payout Quote** `createPayoutQuote`: Creates a short-lived, provider-backed quote for a payout: the exact fee, exchange rate and amount the recipient would receive. No funds move — the quote only becomes a payout when its Quote Token is passed to Create Payout before it expires. Whop requires an Idempotency Key on this route, so retrying with the same key returns the original quote instead of minting a second one.
* **Create Plan** `createPlan`: Creates a pricing plan for a product, defining its billing interval, price, stock and availability to customers.
* **Create Product** `createProduct`: Creates a new product for an account.
* **Create Promo Code** `createPromoCode`: Creates a promo code for an account. Scope it to a product with Product ID or to specific plans with Plan IDs; leave both out to make it account-wide.
* **Create Reaction** `createReaction`: Adds an emoji reaction to a message or forum post, or casts a poll vote when Poll Option ID is set. In forums the reaction is always a like and the Emoji input is ignored. The reaction is visible to everyone who can see the resource.
* **Create Recommendations** `createEconomicIntelligence`: Generates an Economic Intelligence recommendation based on your input. Returns immediately; poll List Economic Intelligence until its `status` is `ready`. Accounts without the feature get 403 "You don't have access to Economic Intelligence yet."
* **Create Resolution Center Case** `createResolutionCenterCase`: Opens a case as the customer, against one of your own payments. This is the buyer side of the resolution centre, so the calling credential must own the payment. Give the payment, the reason and an explanation.
* **Create Setup Intent** `createSetupIntent`: Saves a buyer's payment method for later WITHOUT charging it now - this attaches a real payment instrument to a real person's Whop account. Supply either a Confirmation Token for a method the buyer just entered, or an existing Payment Method ID to re-verify; never both. The buyer may still have a step to finish - 3D Secure, a hosted enrolment, linking a bank - so poll Retrieve Setup Intent Status rather than trusting this response. The response carries a client_secret: treat it as a credential, because it lets the holder drive this setup. Needs payment:charge.
* **Create Shipment** `createShipment`: Attaches a carrier tracking number to a payment and starts tracking it. Whop infers the carrier from the number and begins polling them, so the customer starts seeing delivery updates against that order. Whop exposes no delete route for shipments, so an attachment made here can only be corrected with Update Shipment, not removed.
* **Create Social Account** `createSocialAccount`: Creates, or returns if it already exists, a Whop-managed Facebook page or TikTok account for an account. This provisions a REAL page or account on the external platform, and Delete Social Account only disconnects it - it does not remove the platform account. facebook requires the account's banner_image, logo and description to be set first; tiktok requires its logo. Configure those with Update Account.
* **Create Support Channel** `createSupportChannel`: Open a new support channel between a company team member and a customer. Returns the existing channel if one already exists for that user. This REACHES A REAL PERSON: the customer sees a new support conversation, and set notifications_enabled false to suppress the Whop push (webhooks still fire). Required permissions: `support_chat:create`. The sender is resolved from the company's team: with no team member other than the recipient the API returns 400 "Cannot create support chat: recipient is the bot owner and no other team members exist to send from". There is no delete route for a channel.
* **Create Swap** `createSwap`: MOVES REAL VALUE. Swaps one token for another out of the account's wallet, or converts between fiat currencies in its ledger at the mid-market rate. Crypto swaps settle on-chain in the background and cannot be recalled - poll Retrieve Swap for status. WATCH THE AMOUNT DEFAULT: on a fiat pair, omitting both Amount and To Amount does not mean "do nothing", it means REPAY THE ENTIRE negative To Token balance. Preview with Create Swap Quote first, which moves nothing.
* **Create Swap Quote** `createSwapQuote`: Previews the price of a swap. NO FUNDS MOVE and nothing is saved, so this is the safe way to check a rate before committing. Fiat pairs quote the in-ledger mid-market conversion, which is the same rate Create Swap fills at. Read requires_token_approval on the result - a crypto swap will not go through until the token is approved.
* **Create Team Member** `createTeamMember`: Adds someone to an account's team with a system role. Identify them by exactly one of User ID or Email. If they have not accepted yet, or the email has no Whop account, Whop SENDS THEM A REAL INVITATION EMAIL and returns 202 with {"object":"team_member_invite","invitation_sent":true} rather than a membership. A second request while an invite is already pending fails with 400. Custom roles cannot be granted through the API. Granting workforce is also permitted with just the bounty:create scope.
* **Create Topup** `createTopup`: Add funds to a company's platform balance by CHARGING A STORED PAYMENT METHOD - this spends real money on a real card or bank account and there is no refund route here. Top-ups have no fees or taxes and do not count as revenue. Required permissions: `payment:charge`. An unknown payment_method_id returns 404 "This PaymentToken was not found" and nothing is charged.
* **Create Transfer** `createTransfer`: MOVES REAL MONEY. Type decides how, and it DEFAULTS TO ledger - omitting it still transfers credit between two Whop balances. ledger returns a transfer; wallet_send pushes USDT out of the origin account's Ethereum wallet, which is an on-chain transaction that cannot be recalled; claim_link returns a URL that ANYONE HOLDING IT can redeem, so treat the link itself as bearer funds. Always pass Idempotence Key on ledger transfers and wallet sends so a retry cannot pay twice.
* **Create Verification** `createVerification`: Starts a hosted KYC/KYB verification session, or returns the active one if a session already exists. HANDLES REAL PERSONAL DATA: every field here is identity information, and Whop passes it to its verification provider (Sumsub), so it leaves Whop's own boundary. There is NO delete route for a verification - once a person's identity data is submitted it cannot be withdrawn through this API. Three mutually distinct modes: send nothing beyond Account ID for a plain hosted session; send Documents with Document Type to verify from identity documents directly, with no hosted session; or send Share Token to reuse a verification another Sumsub account already completed for this person.
* **Create Webhook** `createWebhook`: Creates a webhook endpoint that receives Whop event notifications by HTTP POST. The response includes the signing secret, which is only returned here and on Rotate Secret.
* **Deactivate Payment Rule** `deactivatePaymentRule`: Deactivates a payment rule so it stops applying to new payments. It keeps its id and can be turned back on with Activate Payment Rule, which makes this the safe way to pause a rule rather than deleting it.
* **Deactivate Promo Code** `deactivatePromoCode`: Turns off an active promo code so it can no longer be redeemed at checkout. Reversible with Activate Promo Code. Equivalent to Update Promo Code with Status set to inactive.
* **Delete Ad** `deleteAd`: Deletes an ad.
* **Delete Ad Campaign** `deleteAdCampaign`: Deletes an ad campaign and archives it on the ad platform. Cascades to its ad groups and ads.
* **Delete Ad Group** `deleteAdGroup`: Deletes an ad group.
* **Delete Affiliate Override** `deleteOverrideAffiliate`: Deletes a commission override, so the affiliate falls back to the account's default rate. Returns the bare JSON boolean true on success; this route does not return an object. Requires the affiliate:update permission.
* **Delete AI Chat** `deleteAiChat`: Deletes an AI chat thread so it no longer appears in the user's chat list. Needs ai_chat:delete.
* **Delete API Key** `deleteApiKey`: Permanently revokes an API key. Every request using its secret stops authenticating immediately, so make sure nothing in production still holds it. Default and agent-backend keys cannot be deleted.
* **Delete App** `deleteApp`: Deletes an app. It stops resolving within seconds — a website app's site stops serving immediately — and any claimed subdomain stays reserved for a month before anyone can claim it again. This cannot be undone.
* **Delete Audience** `deleteAudience`: Deletes an audience so it is no longer available for ad targeting. Note that the audience also exists on the ad platform's side under platform_audience_ids; removing it from Whop does not guarantee it is gone from there, so check the platform too if the data must not persist.
* **Delete Authorized User** `deleteAuthorizedUser`: Removes an authorized user from a company, REVOKING THEIR ACCESS immediately. ID accepts either the authorized-user record id or the person's user id - in the second form Account ID is required, because a user id alone does not say which company to revoke on.
