# Pinch Payments

<img src="../../.gitbook/assets/connectors/lg/pinch-payments.png" alt="Pinch Payments logo">

Pinch Payments is an Australian payments platform for credit card and direct debit collection. This connector covers payers, payment sources, scheduled and realtime payments, payment links, plans and subscriptions, refunds, transfers and settlement line items, events, webhooks, contacts, fee schedules, tokenisation, and managed-merchant (PayFac) administration. Requests run against either the test or live environment, selected per connection.

| | |
| --- | --- |
| **Category** | [Finance and payments](README.md) |

| **Authentication** | OAuth 2.0 |
| **Slug** | `pinchPayments` |

## Use it

Add Pinch Payments from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.pinchPayments.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

| Action | Slug | What it does |
| --- | --- | --- |
| Calculate Fees | `calculateFees` | Preview the processing fee and surcharge that would apply to a payment before it is taken, so the exact amount can be shown to the customer. Accepts either a tkn_ token, a stored src_ source id, or a bare source type together with the amount in cents. Performs no charge. |
| Calculate Plan Payments | `calculatePlanPayments` | Preview the exact schedule of Payments a Plan would generate for a given start date, without creating a Subscription. Use this to show a customer their future billing dates and amounts before they commit. |
| Cancel Subscription | `cancelSubscription` | Cancel a Subscription so no further scheduled Payments are generated or attempted. Payments already processed are unaffected. |
| Check Auth Health | `checkAuthHealth` | Verify that the connection's access token is valid and report which Pinch merchant and environment it authenticates as. Returns the merchant name, merchant id, the signed-in email and whether the token is operating in the Test or Live environment. Use this as a cheap connection health check. |
| Check Payment Nonce | `checkPaymentNonce` | Check whether a payment nonce has already been consumed, so a retried payment request can be made safely idempotent. Returns the payment previously created with that nonce when one exists. |
| Check Refund Nonce | `checkRefundNonce` | Check whether a refund nonce has already been consumed, so a retried refund request does not issue a duplicate refund. Returns the refund previously created with that nonce when one exists. |
| Create Managed Merchant | `createManagedMerchant` | Onboard a new sub-merchant under this account using the Managed Merchants (PayFac) feature, supplying company details, a disbursement bank account and at least one compliance contact. Pinch rejects this route with "Cannot access this endpoint using test keys", so it only runs with a live application credential. |
| Create or Update Contact | `saveContact` | Create a compliance Contact for the merchant, or update an existing one by supplying its con_ id. Contacts record the owners, directors, shareholders and executives that Pinch requires for KYC, including identity document details. |
| Create or Update Payer | `savePayer` | Create a new Payer, or update an existing one when an id is supplied. A Payer represents the customer that Payments, Payment Links and Subscriptions are taken against. Optionally attaches a payment source in the same call using a token from CaptureJS. Returns the saved payer record including its pyr_ id. |
| Create or Update Plan | `savePlan` | Create a billing Plan describing the schedule of payments a Subscription will generate: any number of fixed point-in-time payments, at most one recurring payment, and optional free periods. Amounts may be fixed in cents or a percentage of a subscription total. |
| Create or Update Scheduled Payment | `savePayment` | Schedule a Payment to be taken from a Payer on a given transaction date, or update an existing scheduled payment by supplying its id. The payer must already have a stored payment source unless a sourceId is given. WARNING: in live mode this debits a real customer. Amounts are in cents. |
| Create or Update Webhook | `saveWebhook` | Register a callback URI to receive Pinch Events, or update an existing one by supplying its wbk_ id. Choose the payload casing and which event types to subscribe to, or leave eventTypes empty for all. The response includes a whsec_ signing secret used to verify the pinch-signature header on every delivery; store it and never expose it. |
| Create Payment Link | `createPaymentLink` | Create a hosted payment page for a Payer and return its shareable URL, so a customer can pay by card or direct debit without any frontend work. Choose which payment methods are allowed, which are surcharged, an optional expiry, and the URL the payer is returned to after paying. |
| Create Payment Source For Payer | `createPaymentSource` | Attach a payment source (bank account or credit card) to an existing Payer so it can be charged later. Credit cards must be supplied as a tkn_ token from CaptureJS. Bank accounts are supplied as bankAccountName, bankAccountBsb and bankAccountNumber. SECURITY: the response echoes the full bank account number and a reusable tkn_ token for the stored instrument. |
| Create Realtime Payment | `createRealtimePayment` | Charge a credit card immediately and return the authorisation result in the same response. Supply either an existing payerId and sourceId, or a tkn_ token from CaptureJS together with the payer's contact details. WARNING: in live mode this captures real funds from a real card. Amounts are in cents. |
| Create Refund | `createRefund` | Refund all or part of a processed Payment back to the customer. WARNING: in live mode this returns real funds and cannot be undone. Supply a nonce to make retries idempotent. Amounts are in cents. |
| Create Subscription | `createSubscription` | Subscribe a Payer to a Plan, which generates the plan's scheduled Payments against that payer. WARNING: in live mode this creates real recurring debits. Supply a totalAmount for percentage-based plans and a sourceId to bill a specific stored payment source. |
| Delete Compliance Document | `deleteComplianceDocument` | Remove a previously uploaded merchant compliance document by its id. Pinch rejects this route with "Cannot access this endpoint using test keys", so it only runs with a live application credential. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Delete Contact | `deleteContact` | Delete a compliance Contact by its con_ id. Take care not to remove the merchant's only primary contact, which compliance requires. |
| Delete Payer | `deletePayer` | Permanently delete a Payer and its stored payment sources. Scheduled Payments belonging to the payer must be removed first. Returns 200 on success. |
| Delete Payment Link | `deletePaymentLink` | Revoke a hosted Payment Link so its public URL can no longer be used to pay. Takes the payment link id. |
| Delete Payment Source | `deletePaymentSource` | Remove a stored payment source from a Payer so it can no longer be charged. Requires both the payer id and the source id. |
| Delete Plan | `deletePlan` | Delete a billing Plan so no new Subscriptions can be created against it. Takes the plan id in pln_ format. |
| Delete Scheduled Payment | `deletePayment` | Cancel and remove a scheduled Payment so it is never attempted. Only payments that have not yet been processed can be deleted. |
| Delete Webhook | `deleteWebhook` | Unregister a webhook by its wbk_ id so Pinch stops delivering events to that callback URI. |
| Get API Application | `getApplication` | Retrieve one registered API Application by its id. SECURITY: application records may expose credential metadata, so restrict who can run this action. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Card Terminal | `getTerminal` | Retrieve one physical card terminal by its id, including its serial number and registration status. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Contact | `getContact` | Retrieve one compliance Contact by its con_ id, including name, role, contact details and any identity document references recorded for KYC. |
| Get Current Merchant Financial Data | `getCurrentMerchantFinancialData` | Retrieve the most recent merchant financial-data record: annual turnover, average ticket size, card-present and card-not-present mix, delivery timeframes and deposit terms. Pinch uses this for underwriting. |
| Get Event | `getEvent` | Retrieve one Event by its evt_ id, returning the same envelope Pinch posts to webhooks: the event id, type, event date, metadata and the type-specific data payload. |
| Get Fee Schedule | `getFeeSchedule` | Retrieve the merchant's current fee schedule: the percentage and fixed fee, cap and zone applied to each payment method and card scheme. Use this to display fees or to reconcile settlement deductions. |
| Get Managed Merchant | `getManagedMerchant` | Retrieve one managed sub-merchant by its mch_ id, including company details, compliance and contact verification status and the disbursement bank account. Pinch rejects this route with "Cannot access this endpoint using test keys", so it only returns data for a live application credential. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Merchant Portal User | `getMerchantUser` | Retrieve one Pinch dashboard user by id. Pinch answers 204 No Content when the id does not match a user in this merchant. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Notification | `getNotification` | Retrieve one in-app notification by id. Pinch answers 403 Forbidden to application (client-credentials) tokens on this route; it appears to require a dashboard user session. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Payer | `getPayer` | Retrieve a single Payer by its Pinch payer id, including contact details, address, metadata and any stored payment sources. Returns 400 with a validation envelope when the payer id does not exist. |
| Get Payment | `getPayment` | Retrieve one Payment by its pmt_ id, including amount, status, transaction date, the payer it belongs to and every processing attempt made against it. |
| Get Payment Link | `getPaymentLink` | Retrieve a single hosted Payment Link by its id, including its amount, payer, expiry, status and public payment URL. |
| Get Plan | `getPlan` | Retrieve one billing Plan by its pln_ id, including its full fixed, recurring and free-period schedule definition. |
| Get Refund | `getRefund` | Retrieve one Refund by its ref_ id, including the payment it refunds, the amount, reason and current status. Note: the Pinch reference documents this route as /refund/{id}, but the live API only serves /refunds/{id}, which is what this action calls. |
| Get Settlement Bank Account | `getSettlementBankAccount` | Retrieve one configured settlement or fee bank account by its id. SECURITY: the response contains the merchant's own bank account and routing numbers — restrict who can run this action. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Settlement Bank Accounts | `getSettlementBankAccounts` | Retrieve the merchant's configured settlement and fee bank accounts. SECURITY: the response contains bank account numbers and routing numbers for the merchant's own accounts — restrict who can run this action. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Get Subscription | `getSubscription` | Retrieve one Subscription by its sub_ id, including the plan it follows, the payer it bills, its status and the payments it has generated. |
| Get Transfer | `getTransfer` | Retrieve one settlement Transfer by its tra_ id, including the settled amount, the transfer date and the bank account it was paid into. |
| Get Webhook | `getWebhook` | Retrieve one registered webhook by its wbk_ id, returning its callback URI and subscribed event types. SECURITY: Pinch returns the webhook's whsec_ signing secret in plaintext in this response — restrict who can run this action. |
| List API Applications | `listApplications` | Retrieve the API Applications registered on the Pinch account. Pinch rejects this route with "Cannot access this endpoint using test keys", so it only returns data for a live application credential. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| List Card Terminals | `listTerminals` | Retrieve the paged list of physical card terminals registered to the merchant for card-present payments. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| List Contacts | `listContacts` | Retrieve a paged list of the merchant's compliance Contacts — the owners, directors, shareholders and executives recorded for KYC. Supports a free-text search filter. |
| List Events | `listEvents` | Retrieve a paged list of Events raised in the Pinch account, optionally narrowed by date range or by a single event type such as payment-created. Every webhook delivery has a corresponding Event here, so this is the poll-based alternative to webhooks. |
| List Managed Merchants | `listManagedMerchants` | Retrieve the sub-merchants created under this account through the Managed Merchants (PayFac) feature, with their company details and onboarding status. Pinch rejects this route with "Cannot access this endpoint using test keys", so it only returns data for a live application credential. |
| List Merchant Financial Data Records | `listMerchantFinancialData` | Retrieve the paged history of merchant financial-data records submitted for underwriting. This collection route is live on the Pinch API but is not published in the vendor's OpenAPI reference, which documents only the /current and save routes. |
| List Merchant Portal Users | `listMerchantUsers` | Retrieve the user accounts that have access to this merchant's Pinch dashboard. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| List Merchants | `listMerchants` | Retrieve the merchant accounts visible to the calling application. This is a platform-level route: Pinch rejects it with "Cannot access this endpoint using test keys", so it only returns data for a live application credential. |
| List Notifications | `listNotifications` | Retrieve the merchant's in-app notifications. Pinch answers 403 Forbidden to application (client-credentials) tokens on this route; it appears to require a dashboard user session. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| List Payers | `listPayers` | Retrieve a paged list of Payers (customers) held against the merchant. Supports an optional free-text filter that searches payer name and email. Returns a paged envelope with page, pageSize, totalPages, totalItems and a data array of payer records. |
| List Payment Links | `listPaymentLinks` | Retrieve a paged list of every hosted Payment Link created by the merchant, with its amount, payer, status and public URL. |
| List Payment Links For Payer | `listPaymentLinksForPayer` | Retrieve the hosted Payment Links issued to one specific Payer, as a paged envelope. Use this to show a customer every outstanding link they have. |
| List Payments For Payer | `listPaymentsForPayer` | Retrieve every Payment, scheduled and processed, belonging to one Payer. Takes the payer id in pyr_ format. The Pinch API returns a bare array here rather than a paged envelope, so this action wraps it in an items property. |
| List Plans | `listPlans` | Retrieve a paged list of every billing Plan defined by the merchant, with its name, fixed payments, recurring payment schedule and free periods. |
| List Processed Payments | `listProcessedPayments` | Retrieve a paged list of Payments that have already been processed, optionally narrowed by transaction date range or by a specific payment (pmt_) or attempt (att_) id. Use this for reconciliation and settlement reporting. |
| List Refunds | `listRefunds` | Retrieve a paged list of Refunds issued by the merchant, optionally narrowed to a date range. Returns each refund's amount, reason, status and the payment it belongs to. |
| List Scheduled Payments | `listScheduledPayments` | Retrieve a paged list of every Payment that is currently scheduled and has not yet been processed. Returns a paged envelope with page, pageSize, totalPages, totalItems and a data array. |
| List Subscriptions | `listSubscriptions` | Retrieve a paged list of every Subscription, with its plan, payer, start date and current status. |
| List Supported Countries | `listSupportedCountries` | Retrieve Pinch's country reference list, giving the alpha-2 and alpha-3 codes, numeric code, display name and whether surcharging is enabled for each country. Useful for populating address and surcharge pickers. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| List Transfer Line Items | `listTransferLineItems` | Retrieve the individual payments, fees, refunds and adjustments that make up one settlement Transfer. Use this to reconcile a bank deposit back to the underlying payments. |
| List Transfers | `listTransfers` | Retrieve the settlement Transfers Pinch has made to the merchant's bank account. Each transfer batches the payments settled on a given date. The Pinch API returns a bare array here, which this action wraps in an items property. |
| List Webhooks | `listWebhooks` | Retrieve every webhook registered on the Pinch account, with its callback URI and subscribed event types. The Pinch API returns a bare array here, which this action wraps in an items property. SECURITY: Pinch returns each webhook's whsec_ signing secret in plaintext in this listing — restrict who can run this action. |
| Ping API Service | `pingApiService` | Liveness probe for the Pinch API itself. Returns 200 with an empty body when the service is reachable. Use Check Auth Health instead when you need to validate the connection's credentials. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Save Merchant Financial Data | `saveMerchantFinancialData` | Submit or update the merchant's financial profile for underwriting: annual turnover, average ticket size, deposit terms, delivery timeframes and the card-entry and channel mix. The MOTO, in-store and internet percentages must sum to 1, and the delivery percentages must sum to 1. All percentages are decimals. |
| Search Merchants | `searchMerchants` | Search the merchant accounts visible to the calling application, returning a paged envelope. Unlike the plain merchants list route this one is available to test keys. This route is live on the Pinch API but is not published in the vendor's reference documentation. |
| Tokenise Payment Source | `tokenisePaymentSource` | Exchange raw credit card or bank account details for a single-use tkn_ token that can be stored against a Payer or charged. Authenticated with the merchant's publishable key rather than the secret key. Prefer the browser-side CaptureJS library where possible so card data never touches your servers; use this server-side route only where your PCI scope allows it. |
| Update Merchant | `updateMerchant` | Update the calling merchant's own company details, addresses, compliance contacts and settlement bank account. WARNING: this replaces the merchant profile, including the bank account settlements are paid into. Send the complete desired state, not a partial patch. |
| Upload Compliance Document | `uploadComplianceDocument` | Upload a supporting document for merchant compliance, such as an identity document, business registration or financial statement. The Pinch route takes a multipart/form-data body with a File part, a DocumentType and, for identity documents, the ContactId the document belongs to. |

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Bank Results Returned | `bank-results` | Fires when a batch of bank-account (direct debit) transactions returns from the bank, carrying approvals and dishonours. Subscribe to this if you take direct debits, or you will miss failed payments. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Compliance Status Updated | `compliance-updated` | Fires when the merchant's or a managed merchant's compliance/KYC status changes. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Dispute Created | `dispute-created` | Fires when a cardholder raises a chargeback or dispute against a Payment. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Dispute Updated | `dispute-updated` | Fires when an existing dispute changes status or evidence is required. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Merchant Updated | `merchant-updated` | Fires when the merchant profile is changed. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Payer Created | `payer-created` | Fires when a new Payer is created. payloadSchema CAPTURED LIVE from Pinch event evt_ha63mOZw9HyggM. SIGNING: every delivery carries pinch-signature: t=&lt;unix&gt;,v2=&lt;hex HMAC-SHA256 of "{t}.{raw body}" keyed with the whsec_ secret returned by Create or Update Webhook&gt;; verify it and reject a t older than 5 minutes. SECURITY: Data.Payer.Sources[] carries the full bank account number and a reusable tkn_ token, and Data.Payer.Agreements[].AnonymousViewToken is an unauthenticated view token for the direct-debit agreement. |
| Payer Updated | `payer-updated` | Fires when an existing Payer record is changed. payloadSchema modelled from the Pinch Events documentation; the envelope matches the captured payer-created delivery. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Payment Created | `payment-created` | Fires when a Payment is created, whether scheduled or realtime. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Realtime Payment Processed | `realtime-payment` | Fires when a realtime card payment is processed. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Refund Created | `refund-created` | Fires when a Refund is issued against a Payment. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Refund Updated | `refund-updated` | Fires when a Refund changes status, for example from pending to processed. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Scheduled Payments Processed | `scheduled-process` | Fires each business day when the scheduled Payment run completes. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Settlement Transfer Made | `transfer` | Fires when Pinch transfers settled funds to the merchant's bank account. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Subscription Cancelled | `subscription-cancelled` | Fires when a Subscription is cancelled before it completes. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Subscription Completed | `subscription-complete` | Fires when a Subscription reaches the end of its Plan schedule. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
| Subscription Created | `subscription-created` | Fires when a Payer is subscribed to a Plan. payloadSchema modelled from the Pinch Events documentation. Verify the pinch-signature HMAC-SHA256 over "{t}.{raw body}" using the webhook's whsec_ secret. |
