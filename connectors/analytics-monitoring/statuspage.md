# Statuspage

<img src="../../.gitbook/assets/connectors/lg/statuspage.png" alt="Statuspage logo">

Manage status pages, components and component groups, incidents and incident updates, postmortems, scheduled maintenance, uptime reporting, custom metrics and metrics providers, page and incident subscribers, audience-specific page access users and groups, the status embed widget, and organization users and permissions. Single host https://api.statuspage.io/v1 with API key authentication sent as an Authorization: OAuth header.

## Use it

Add Statuspage from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.statuspage.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Component Status Updated</td><td><code>componentUpdate</code></td><td>Sent each time a component changes status. Statuspage dispatches this only for status transitions, not for changes to a component's name or position, and the payload carries both the old and the new status. Statuspage sends no event-type field in the payload, so the two events are told apart by shape: a component notification carries component_update and a incident notification carries incident. Statuspage does not sign webhook deliveries, so no signature verification is configured. Webhook notifications must be enabled on the page first (Subscribers &gt; Options &gt; Settings &gt; select Webhook as a delivery type), otherwise Statuspage rejects webhook subscriber creation.</td></tr><tr><td>Incident Created Or Updated</td><td><code>incidentUpdate</code></td><td>Sent each time an incident is created or updated, including scheduled maintenance transitions and postmortem publication. The payload carries the full incident together with all of its incident updates. Statuspage sends no event-type field in the payload, so the two events are told apart by shape: a component notification carries component_update and a incident notification carries incident. Statuspage does not sign webhook deliveries, so no signature verification is configured. Webhook notifications must be enabled on the page first (Subscribers &gt; Options &gt; Settings &gt; select Webhook as a delivery type), otherwise Statuspage rejects webhook subscriber creation.</td></tr></tbody></table>
