# Instatus

Instatus status pages, uptime monitoring and incident communication. Manage status pages, workspaces, components, incidents and incident updates, scheduled maintenances, templates, general notices, outages, uptime metrics, audience groups, subscribers, teammates, HTTP and cron monitors, monitor alerts and groups, routing rules, escalation policies, on-call schedules and monitoring integrations.

## Use it

Add Instatus from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.instatus.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

| Event | Id | When it fires |
| --- | --- | --- |
| Component Status Changed | `component_update` | Fires when a component changes status. Identified by top-level 'component_update' and 'component' objects; Instatus sends no event-type field and a webhook subscriber receives every event type on the same trigger URL. Signed with a per-subscriber secret in x-instatus-webhook-signature (HMAC-SHA256 hex of the JSON body) which the engine cannot resolve, so verification is left to the consumer. Payload schema modelled from https://instatus.com/help/webhooks, not captured from a live delivery. |
| Incident Added Or Updated | `incident` | Fires when an incident is published or updated on the status page. Instatus sends NO event-type field: a delivery is identified by carrying a top-level 'incident' object. A webhook subscriber receives every event type - Instatus has no per-event-type subscription, so all three events arrive on the same trigger URL. Instatus signs each delivery with a PER-SUBSCRIBER secret in the x-instatus-webhook-signature header (HMAC-SHA256 hex of the JSON body); the fastn engine can only resolve an HMAC secret from an auth provider client secret, so signature verification is left unset here and must be done by the consumer. Payload schema modelled from the vendor's documented format at https://instatus.com/help/webhooks, not captured from a live delivery. |
| Maintenance Added Or Updated | `maintenance` | Fires when a scheduled maintenance is published or updated. Identified by a top-level 'maintenance' object; Instatus sends no event-type field and a webhook subscriber receives every event type on the same trigger URL. Signed with a per-subscriber secret in x-instatus-webhook-signature (HMAC-SHA256 hex of the JSON body) which the engine cannot resolve, so verification is left to the consumer. Payload schema modelled from https://instatus.com/help/webhooks, not captured from a live delivery. |
