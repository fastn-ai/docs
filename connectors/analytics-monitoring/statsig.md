## Setup

Your customers enter their API key for Statsig when they connect. Nothing else needs setting up.

## Use it

Add Statsig from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.statsig.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Actions

<table><thead><tr><th width="240">Action</th><th width="260">Slug</th><th>What it does</th></tr></thead><tbody><tr><td>Check Feature Gates</td><td><code>checkFeatureGates</code></td><td>Evaluates one or more Statsig feature gates for a user and returns whether each gate passes, along with the rule and group that matched. Supply either a single gate name or an array of gate names, not both. With a single gate name the response is one flat result object; with an array it is an object keyed by gate name whose values have that same shape. Statsig automatically logs an exposure event for each evaluation unless exposure logging is disabled in the metadata.</td></tr><tr><td>Get Dynamic Config Or Experiment</td><td><code>getDynamicConfigOrExperiment</code></td><td>Fetches the configuration values a user receives from a dynamic config or an experiment. Statsig determines which of the two the name refers to automatically. An exposure event is logged automatically unless exposure logging is disabled in the metadata.</td></tr><tr><td>Get ID Lists</td><td><code>getIdLists</code></td><td>Returns the ID-list segments the project uses for targeting, each with the storage URL, size and creation time a client needs to download it. An empty object means the project defines no ID lists.</td></tr><tr><td>Get Layer Parameters</td><td><code>getLayerParameters</code></td><td>Fetches the parameter values a user receives from a Statsig layer. Layers let several experiments share a pool of parameters. An exposure event is logged automatically unless exposure logging is disabled in the metadata. A layer name that does not exist in the project</td></tr><tr><td>Get Ranked List For Contextual Bandit</td><td><code>getRankedListForContextualBandit</code></td><td>Returns the variants of a Statsig contextual multi-armed bandit (Autotune AI) ranked by predicted performance for a given user context. A config name that is not a contextual bandit, or does not exist</td></tr><tr><td>Initialize User</td><td><code>initializeUser</code></td><td>Returns every feature gate, dynamic config, experiment and layer evaluated for a single user in one call, exactly as a Statsig client SDK receives them on start-up. Configuration names are hashed with the algorithm named in the hash_used field of the response. Use it to hydrate an application with a user's full Statsig state instead of evaluating each configuration separately.</td></tr><tr><td>Log Custom Events</td><td><code>logCustomEvents</code></td><td>Logs one or more custom events to Statsig for analytics and metric calculation. Each event can carry its own user, value, timestamp and metadata, or inherit a shared user supplied at the top level.</td></tr><tr><td>Log Custom Exposure Events</td><td><code>logCustomExposureEvents</code></td><td>Manually logs exposure events for experiments, dynamic configs or feature gates. It takes one event per call, unlike Log Custom Events which takes a batch. Requires a Server Secret Key.</td></tr></tbody></table>

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Custom Event</td><td><code>custom_event</code></td><td>Sent for every custom event logged into the project, whatever its name. Statsig puts the customer's own event name in eventName, so this event id is a placeholder for the whole class rather than a literal value found in the payload - filter on eventName inside your workflow. That is also why this connector deliberately sets no event key: a fixed event key would silently drop every custom event whose name is not declared here, so all Statsig deliveries fan out to every bound trigger instead. Setup is manual, in the Statsig console: open Project Settings &gt; Integrations, enable the Generic Webhook integration, paste the fastn trigger URL, select Enable, then use Event Filtering to choose which events are forwarded. Statsig exposes no webhook-registration API, so fastn cannot subscribe on the customer's behalf. Deliveries arrive as a JSON array batch and Statsig does not sign them.</td></tr><tr><td>Dynamic Config Exposure</td><td><code>statsig::config_exposure</code></td><td>Sent when Statsig evaluates a dynamic config for a user.
