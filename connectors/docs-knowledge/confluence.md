# Confluence

Atlassian Confluence Cloud connector (REST API v2) — pages, blog posts, comments (footer/inline), attachments, custom content, labels, likes, versions, children/ancestors/descendants, spaces & space/content properties, tasks, users, whiteboards, databases, folders, smart links. Via api.atlassian.com OAuth 2.0 (3LO); cloudId input on every action.

## Use it

Add Confluence from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.confluence.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

| Attachment Archived | `attachment_archived` | An attachment was archived. Atlassian does not publish the payload for this event; the schema below models the documented Confluence content webhook shape as the default and the exact key set may vary. Setup (customer side): Confluence Cloud has no supported REST API for managing webhooks, so this event cannot be subscribed to programmatically by fastn. The customer must route it to the fastn webhook URL by one of: (1) a Forge app whose trigger module subscribes to the product event avi:confluence:archived:attachment and forwards the payload to the fastn URL (the supported path — Connect is closed to new Marketplace apps since 2025-09-17); (2) an Atlassian Connect descriptor already installed on the site declaring {"event": "attachment_archived", "url": "&lt;fastn webhook URL&gt;"} in modules.webhooks; (3) the unsupported internal endpoint POST /wiki/rest/webhooks/1.0/webhook with {"name":"fastn","url":"&lt;fastn webhook URL&gt;","events":["attachment_archived"]}. |
