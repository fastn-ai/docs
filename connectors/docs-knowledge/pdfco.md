# PDF.co

<img src="../../.gitbook/assets/connectors/lg/pdfco.png" alt="PDF.co logo">

This connector covers the whole PDF.co v1 API: PDF conversion to and from every supported format, merge and split, page editing, text and image search-and-replace, rotation, optimisation and compression, form field reading, barcode generation and reading, OCR (make searchable/unsearchable), the document parser and its templates, the AI invoice parser, document classification, attachments, email decoding, attachment extraction and sending, file upload and storage, presigned upload URLs, file hashing and deletion, HTML templates, background job status checks and the account credit balance.

## Use it

Add PDF.co from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.pdfco.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Job Completed</td><td><code>success</code></td><td>Fires when a PDF.co job that was started asynchronously finishes successfully. PDF.co has NO webhook registration API: the only way to receive this event is to pass the fastn trigger URL as the Callback URL on the action itself. Setup: (1) copy this trigger's URL, (2) in the PDF.co action you want to be notified about, set Run Asynchronously to true and paste the URL into Callback URL, (3) run the action. PDF.co then POSTs the finished job to the trigger URL. This is per request, not per account, so it has to be done on every action you want events from. The callback endpoint must answer within 20-30 seconds or PDF.co retries up to 3 times. Payload schema captured from a real delivery on 2026-09-16.</td></tr><tr><td>Job Failed</td><td><code>failed</code></td><td>Fires when a PDF.co job that was started asynchronously fails, for example because the source file could not be downloaded. PDF.co has NO webhook registration API: the only way to receive this event is to pass the fastn trigger URL as the Callback URL on the action itself. Setup: (1) copy this trigger's URL, (2) in the PDF.co action, set Run Asynchronously to true and paste the URL into Callback URL, (3) run the action. This is per request, not per account. Note that a failed delivery carries no jobId and no output url, only the failure message. Payload schema captured from a real delivery on 2026-09-16.</td></tr></tbody></table>
