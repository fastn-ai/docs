## Setup

Your customers enter their API key for ZenRows when they connect. Nothing else needs setting up.

## Use it

Add ZenRows from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.zenrows.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Scraping Run Completed</td><td><code>run.completed</code></td><td>ZenRows POSTs this to the receiver attached to a batch scraping job when that job's run finishes, whether it succeeded, failed or was stopped. Deliveries are at-least-once, so deduplicate on the X-ZenRows-Event-Id header. When the webhook was registered with signature true, each delivery also carries X-Signature in the form t=&lt;unix&gt;,v1=&lt;hex&gt;,kid=&lt;key id&gt;, where v1 is HMAC-SHA256 over "&lt;t&gt;.&lt;raw body&gt;" using the base64 secret returned once by Rotate HMAC Key. Treat the run and job identifiers as authoritative and re-read the job with Get Scraping Job before acting.</td></tr></tbody></table>
