## Setup

Your customers enter their API key for Lumify when they connect. Nothing else needs setting up.

## Use it

Add Lumify from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.lumify.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Injury Status Changed</td><td><code>injury</code></td><td>Fires on a material or critical player availability transition for an upcoming event, such as a first-seen out or a change from questionable to out. Routine information-level tags and unchanged reconfirmations never fire, and transitions are de-duplicated. Beta coverage is NFL and MLB. Each delivery costs half a credit. Verify Lumify-Signature downstream with the per-subscription signing secret.</td></tr><tr><td>Line Moved</td><td><code>line_move</code></td><td>Fires once per event per ingest cycle, roughly every ten minutes, when a main line's point changes or its American price moves by at least five cents. Only main lines on live or imminent games are pushed; alternate rungs and one-to-four-cent juice ticks are not. Lumify rejects a platform-wide line_move subscription, so you MUST supply either the Sport or the Event ID input when subscribing to this event. Verify Lumify-Signature downstream with the per-subscription signing secret.</td></tr><tr><td>Score Changed</td><td><code>score</code></td><td>Fires when the score of an event changes. Supply the optional Sport input to restrict deliveries to one sport, or the Event ID input to restrict them to a single event. This is the highest-frequency event type and costs the least per delivery. Signature verification is not configured here: Lumify issues a separate signing secret per subscription (returned once by Create Webhook Subscription) and the fastn engine can only resolve one connector-level HMAC secret, so verify Lumify-Signature downstream using the secret you stored at subscribe time.</td></tr><tr><td>Status Changed</td><td><code>status</code></td><td>Fires when an event transitions status, for example from scheduled to in progress or to final. Supply the optional Sport or Event ID input to narrow deliveries. Signature verification is not configured here: verify Lumify-Signature downstream with the per-subscription signing secret returned by Create Webhook Subscription.</td></tr></tbody></table>
