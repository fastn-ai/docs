## Setup

Your customers enter their API key for Linkly when they connect. Nothing else needs setting up.

## Connect in Fastn

Your customers connect Linkly from your widget. To connect an account yourself:

1. Go to **Build → Integrations → Connectors** and search for **Linkly**.
2. Select **Connect** on the Linkly card.

   <figure><img src="../../.gitbook/assets/connector-guides/fastn/connect-search.png" alt="The Connectors page in Fastn with ServiceNow typed in the search box and the ServiceNow card showing a Connect button"><figcaption><p>Search for the connector, then select Connect on its card. ServiceNow is shown here.</p></figcaption></figure>

3. Fill in the fields the form asks for, using the values from [Setup](#setup) above. Then select **Connect**.

   <figure><img src="../../.gitbook/assets/connector-guides/fastn/connect-credentials.png" alt="The Connect ServiceNow dialog with an optional account name and the Instance, Username and Password fields, and Cancel and Connect buttons"><figcaption><p>A connect form that asks for credentials. Each connector asks for its own fields.</p></figcaption></figure>

4. Check that the connection appears under **Operate → Connections** with the status `Active`. Your workflows can now use Linkly's actions.

For more detail, see [Connect an app](../../build/connectors/connect-an-app.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Link Clicked</td><td><code>click</code></td><td>Fires every time a Linkly short link in the subscribed workspace is visited. The payload carries the full link configuration plus the click's request metadata: geo (country, is_eu_country, city, region, isp), browser_name, platform, referer, user_agent, accept_language, bot_name (null for humans), the resolved destination and any forwarded query params.</td></tr><tr><td>Link Created</td><td><code>link.created</code></td><td>Fires when a new short link is created in the subscribed workspace, by the API or in the Linkly UI.</td></tr><tr><td>Link Deleted</td><td><code>link.deleted</code></td><td>Fires when a short link is deleted from the subscribed workspace.</td></tr><tr><td>Link Updated</td><td><code>link.updated</code></td><td>Fires when an existing short link in the subscribed workspace is modified, including changes made through Save Link or Save Links Bulk.</td></tr></tbody></table>
