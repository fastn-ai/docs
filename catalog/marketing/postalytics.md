## Setup

Your customers enter their username and password for Postalytics when they connect. Nothing else needs setting up.

## Use it

Add Postalytics from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.postalytics.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Campaign Mail Tracking Event</td><td><code>campaign_mail_event</code></td><td>Fires for mail piece tracking events of one Postalytics campaign. Postalytics allows exactly one webhook URL per campaign (identified by the campaign drop id, passed as the dropId input), so all event types for that campaign arrive at the same trigger; the integer eventType field tells them apart: 0 Created, 9 Addressed, 10 Printed, 11 Mailed, 4 In Transit, 5 In Local Area, 6 Processed for Delivery, 2 Re-Routed, 3 Return to Sender, 7 pURL Opened, 8 pURL Completed. Which event types are sent is chosen in the Postalytics app: Username menu &gt; Webhooks &gt; edit (pen icon) on the campaign. Requires a Pro or higher plan. Postalytics does not sign deliveries.</td></tr></tbody></table>
