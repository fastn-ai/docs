## Setup

Your customers enter their username and password for ChartMogul when they connect. Nothing else needs setting up.

## Use it

Add ChartMogul from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.chartMogul.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>MRR Movement</td><td><code>mrr_movement</code></td><td>Fires whenever ChartMogul records a real-time customer-level MRR movement - new business, churn, expansion, contraction or reactivation. The specific movement is in the payload's movement_type field. SETUP (required, once per ChartMogul account): in ChartMogul go to Settings &gt; Destinations, click ADD DESTINATION, choose Webhook, enter a Name, paste this trigger's Fastn URL into the URL field, optionally tick 'Include custom attributes in webhook payload', then click SAVE. ChartMogul delivers nothing until that destination is saved. Note that ChartMogul does NOT fire this event for MRR changes caused by historical edits, customer merges, App Store Connect or Google Play integrations, or changes that do not alter the MRR amount.
