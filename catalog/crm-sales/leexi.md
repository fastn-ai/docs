## Setup

Your customers enter their username and password for Leexi when they connect. Nothing else needs setting up.

## Use it

Add Leexi from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.leexi.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Call Processed</td><td><code>call.processed</code></td><td>Fires once Leexi has finished processing a call or meeting: the recording is transcribed, the AI summary, chapters, topics and next steps are generated. This is the only event type Leexi emits. Leexi has no webhook registration API, so the customer must register the endpoint by hand: sign in at https://app.leexi.ai, open Settings &gt; Advanced &gt; Webhooks, click Add, then enter a Name, paste the Fastn trigger URL into URL and optionally a Description, and Save. Leexi immediately posts a test event and only activates the webhook once your endpoint answers 2xx. Only ONE webhook URL is supported per Leexi company, and its scope (all company calls, only calls linked to the user, or custom access rules) is chosen in that same screen. Requests are NOT signed, so there is no signature to verify; restrict the endpoint by obscurity of the trigger URL. Leexi retries a failing delivery 10 times (10s, 1m, 5m, 15m, 30m, 1h, 6h, then every 24h) and then deactivates the webhook automatically.</td></tr></tbody></table>
