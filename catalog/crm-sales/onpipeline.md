## Setup

Your customers enter their API token for Onpipeline when they connect. Nothing else needs setting up.

## Use it

Add Onpipeline from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.onpipeline.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>Calendar Event Changed</td><td><code>event</code></td><td>Fires when a calendar event (task, call, email, meeting or deadline) is created or updated in Onpipeline (Zone=event). The POST body is the event object as returned by List Events. No event-type field is sent.</td></tr><tr><td>Deal Changed</td><td><code>deal</code></td><td>Fires when a deal is created, updated or deleted in Onpipeline. Onpipeline registers one webhook per zone (Zone=deal) and POSTs the deal object exactly as returned by List Deals. The payload carries no event-type field, so routing relies on the per-zone subscription.</td></tr><tr><td>Organization Changed</td><td><code>org</code></td><td>Fires when an organization is created, updated or deleted in Onpipeline (Zone=org). The POST body is the organization object as returned by List Organizations. No event-type field is sent.</td></tr><tr><td>Person Changed</td><td><code>person</code></td><td>Fires when a contact person is created, updated or deleted in Onpipeline (Zone=person). The POST body is the person object as returned by List Persons. No event-type field is sent.</td></tr></tbody></table>
