## Setup

Your customers enter their API key or token for GoDial when they connect. Nothing else needs setting up.

## Use it

Add GoDial from **Build → Integrations → Connectors** and connect an account, as in [Connect a system](../../build/connectors/connect-a-system.md). In workflow code, call an action as `fastn.connector.godial.<action>()`, with the action's slug from the table below. See [Workflow runtime API](../../reference/workflow-runtime.md).

## Events

Start a workflow when one of these happens, with an [app event trigger](../../build/triggers/README.md).

<table><thead><tr><th width="240">Event</th><th width="260">Id</th><th>When it fires</th></tr></thead><tbody><tr><td>After Call</td><td><code>afterCall</code></td><td>Fires after a call is completed in GoDial. GoDial has no webhook registration API (its External API token is rejected on every non-external route with "Api Manager is only able to access external apis"), so a GoDial manager must register the Fastn webhook URL manually: GoDial dashboard &gt; Integrations &gt; Web Hook &gt; enable the webhook, paste the Fastn webhook URL into Target URL, optionally turn on Custom Headers and add a header key and value, switch on the After Call event, then click Save. GoDial allows one webhook URL per company and does not publish a payload schema or an event-type field, so the payload below is the recommended field set, not a vendor contract; if both After Call and Contact Update are enabled on the same URL, route on the payload content in your workflow.</td></tr><tr><td>Contact Update</td><td><code>contactUpdate</code></td><td>Fires after a contact is updated in GoDial. GoDial has no webhook registration API, so a GoDial manager must register the Fastn webhook URL manually: GoDial dashboard &gt; Integrations &gt; Web Hook &gt; enable the webhook, paste the Fastn webhook URL into Target URL, optionally turn on Custom Headers and add a header key and value, switch on the Contact Update event, then click Save. GoDial allows one webhook URL per company and does not publish a payload schema or an event-type field, so the payload below is the recommended field set (mirroring the contact object returned by the External API), not a vendor contract.</td></tr></tbody></table>
